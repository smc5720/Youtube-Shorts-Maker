# 편집 앱

`outputs/run-*/`를 프로젝트로 열고 `project.json`을 고쳐 저장하는 앱이다.
스택은 **Electron + React**, 백엔드는 앱이 자식으로 띄우는 **Python 프로세스 + stdio JSON
Lines**다 — 결정과 근거는 [PRD 14.1](../docs/PRD.md), 화면 기준은
[D2 확정 스펙](../docs/design/d2-app-design-spec.md), 밟은 함정은 루트 `CLAUDE.md`에 있다.

화면이 둘이다.

- **장면** — 장면 목록 · 세로형 프리뷰 · 속성 패널 3분할. 장면을 고르면 그 장면의 대표 프레임이
  뜬다. 속성 패널에서 장면 길이 · 자막 문구 · 텍스트 오버레이 · 자막 스타일 · 배경 · 볼륨을
  고치고 렌더를 실행한다
- **문제 편집** — 좌 목록 + 우 폼 2분할. 질문·정답·해설·난이도·카운트다운을 고치고, 순서를
  바꾸고, 문제를 더하고 지운다. **프리뷰가 없다** — 콘텐츠를 고쳐도 `scenes.json`은 그대로라
  그림이 바뀌지 않는다

**앱에서 고친 것이 곧바로 영상에 반영되지는 않는다.** 낭독 문구를 고치거나 순서·개수를 바꾸면
앱은 낡았다고 **표시만** 하고, 다시 만드는 것은 재생성이다. 낡음은 두 종류이고(자막만 / 음성까지)
색은 둘 다 파랑이며 아이콘 모양과 문구로 갈린다.

## 실행

저장소 루트에 `.venv`가 있고 파이썬 의존성이 설치돼 있어야 한다 (루트 README 참조).
FFmpeg는 없어도 앱이 뜨고, 없다는 사실을 첫 화면에서 말한다.

```bash
cd app
npm install
npm start        # 빌드하고 앱을 띄운다
npm run smoke    # 사람 없이 완료 조건을 밟고 app/smoke/results.json을 남긴다
npm run typecheck
```

| 환경 변수 | 쓰임 |
| --- | --- |
| `SHORTS_PYTHON` | 백엔드를 띄울 인터프리터. 기본은 저장소의 `.venv` |
| `SHORTS_APP_LOG` | 앱 로그 파일. 기본은 `userData/app.log` |

**Windows에서 Electron의 stdout은 부모 셸에 붙지 않는다.** 앱이 빈 화면에서 멈췄다면 콘솔이
아니라 로그 파일을 본다.

## 배치

```
app/
  electron/main.js      백엔드 spawn · IPC · 창 · 메뉴 · 닫기 확인
  electron/preload.js   렌더러에 열어 주는 것의 전부 (window.api)
  electron/smoke.js     --smoke 시나리오
  smoke/run.mjs         스모크 오케스트레이션 (앱을 여러 번 띄운다)
  smoke/make_run.py     스모크가 열 run 디렉터리를 만든다
  src/                  React 렌더러 — App.tsx, scenes.ts, components/, styles/
  src/types/            **타입 전용 편집기.** 콘텐츠 필드를 아는 유일한 앱 코드다
```

## 이 앱의 뼈대 — 네 경계

- **렌더러는 Node도 파일 시스템도 백엔드 프로세스도 보지 못한다.** `contextIsolation`과
  `sandbox`가 켜져 있고 통로는 preload가 연 `window.api`뿐이다.
- **main은 프로젝트 내용을 들지 않는다.** 편집 상태는 렌더러가, 파일은 백엔드가 소유한다.
  main이 하는 일은 요청을 나르는 것과 창을 닫을지 판단하는 것뿐이다.
- **백엔드는 프레임워크를 모른다.** stdin/stdout으로만 말하므로 프레임워크를 갈아도 그대로다.
  **앱이 죽으면 백엔드도 죽는다** — 그렇게 만드는 코드가 따로 있는 것이 아니라 stdin이 닫히면
  백엔드의 읽기 루프가 끝난다.
- **셸은 콘텐츠의 필드를 모른다.** `quiz.json`의 필드를 아는 것은 `src/types/`에 등록된 모듈뿐
  이고 셸은 `ContentItem` 다섯 칸과 폼 컴포넌트만 본다 — 백엔드도 파일명과 검증을 레지스트리
  (`ShortsType.content_schema`)에서 받는다. 등록되지 않은 타입이면 그 화면만 없고 나머지는
  그대로 돈다.

## 알아 둘 것

- **사람이 얹은 편집은 전부 `project.json`에 있다** — 장면 길이·자막 문구·오버레이가
  `render.scene_overrides`의 한 항목에 함께 붙고 `scenes.json`은 앱이 쓰지 않는다. 프리셋 이름과
  오버레이 후보 목록도 앱에 없다(백엔드의 `presets`가 보낸다). 이유는 루트 `CLAUDE.md`와
  PRD 14.1에 있다.
- **저장은 임시 파일에 쓰고 교체한다** (`api.write_atomically`). 검증이 쓰기보다 먼저이므로
  계약을 어긴 편집은 파일에 닿지 않고, 쓰다 실패해도 원본이 남는다.
- **장면을 고르는 것은 즉시(3~5ms), 값을 고치면 2~3초 기다린다.** 프레임을 프로세스 하나로 전부
  만들어 캐시에 넣고 프로젝트가 바뀌면 캐시를 통째로 버린다 — 그래서 대기 표현이 두 가지다.
  `review`와 `audio`는 프레임에 닿지 않아 프리뷰를 다시 만들지 않는다.
- **렌더는 앱이 들고 있는 프로젝트로 돈다.** **저장하지 않은 편집도 결과에 들어가고** 그 사실이
  렌더 화면의 경고 목록에 뜬다. 막는 것은 `flagged`·`unverified` 확인 하나뿐이고 낡음은 알리기만
  한다. 렌더는 한 번에 하나이며 두 번째 요청은 백엔드가 `busy`로 거절한다.
- **네트워크로 나가지 않는다.** 폰트는 번들 Pretendard, 아이콘은 번들 Lucide이고 `index.html`의
  CSP가 `default-src 'none'`이다. main이 `file:` 아닌 요청을 세어 두므로 스모크가 "시도조차
  없었다"를 확인한다.
- **프리뷰와 렌더 스모크는 FFmpeg를 요구한다** — 실제 프레임과 실제 mp4가 그 시나리오들의
  절반이라 대역으로 바꾸면 확인하려는 것이 확인되지 않는다. 나머지는 FFmpeg 없이 돈다.
