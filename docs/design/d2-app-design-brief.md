# D2 앱 UI 디자인 발주서

> **1차 배치 수령 완료.** 이 문서는 무엇을 요청했는지의 기록이고, 구현 기준은
> [`d2-app-design-spec.md`](d2-app-design-spec.md)다. 수령한 시안을 저장소의 확정값과
> 대조해 정리한 결과가 거기 있고, 둘이 다르면 그쪽이 이긴다.
> 원본 시안: [Claude Design 프로젝트](https://claude.ai/design/p/19628b14-e90d-459a-ae18-9cb1837ebe17)
>
> 수령 범위는 5.2(S2) · 5.3(S3) · 5.5(S5) · 6장(상태) · 7장(토큰·인벤토리)이다.
> **2차 배치 발주 범위는 10장에 있고 S4 잔여 둘로 좁혀졌다** — S4의 네 컨트롤(자막 스타일 ·
> 배경 · 장면 길이 · 볼륨)이 S2 속성 패널에 이미 들어왔기 때문이다 (확정 스펙 0장).
> **S1은 발주하지 않는다** — #26이 토큰·인벤토리로 조립해 이미 동작하므로, 지금 시안을 받으면
> 이미 머지된 화면을 다시 손대는 비용만 생긴다.

YouTube Shorts Maker의 **편집 앱 화면 디자인**(D2) 발주 문서다.
영상 안 화면 디자인(D1)은 [별도 발주](d1-video-design-brief.md)로 수령을 마쳤고,
확정 스펙은 [`d1-video-design-spec.md`](d1-video-design-spec.md)에 있다.

**D1과 D2는 다른 화면이다.** D1은 FFmpeg가 영상 안에 그리는 것, D2는 그 영상을 편집하는
데스크톱 앱이다. 다만 **앱 화면 안에 D1 결과가 프리뷰로 들어가므로** 둘이 나란히 놓였을 때
충돌하지 않아야 한다 (4장).

이 문서의 제약은 임의 가이드가 아니라 **프로토타입에서 실측한 값**이다.
제약을 벗어난 시안은 구현 비용이 수 배로 늘거나 구현할 수 없다.

## 1. 무엇을 만드는가

주제 하나를 입력하면 세로형 상식 퀴즈 쇼츠를 자동 생성하는 도구의 **편집 앱**이다.
CLI가 먼저 영상 한 편을 통째로 만들어 놓고, 앱은 그 결과를 **열어서 검수하고 고친 뒤 다시
내보내는** 역할을 한다. 빈 화면에서 영상을 조립하는 편집기가 아니다.

```
CLI 실행  →  run 디렉터리(초안 영상 + 산출 파일)  →  [ 앱: 열기 → 검수 → 수정 → 렌더 ]  →  최종 MP4
```

- 사용자는 반복적으로 쇼츠를 만드는 **개인 크리에이터 1인**이다. 협업·계정·공유 개념이 없다
- **로컬 전용 데스크톱 앱이다.** 네트워크 호출이 없고 업로드 기능도 없다 (PRD 3장 비목표)
- 앱이 존재하는 이유는 **LLM이 만든 내용을 사람이 검수하기 위해서다.** 자동 검증이 미심쩍다고
  표시한 문제를 사람이 확인하지 않고 영상이 나가는 일이 없어야 한다 (5.3, 5.5)
- **복잡한 멀티트랙 전문 편집기를 만들지 않는다** (PRD 3장). 타임라인 트랙, 키프레임,
  트랜지션 편집은 범위 밖이다

### 영상 한 편의 구조

앱이 다루는 대상이므로 알아 둘 것. 장면이 아래 순서로 이어진다.

```
hook  →  [ question → countdown → answer ] x 문제 수  →  cta
```

- 문제 수는 3~5개, 실제 총 길이는 약 38~58초 (4문제 기준 약 48초)
- **목표 범위는 45~60초다.** 실제 산출이 그 아래로 내려갈 수 있어 **총 길이가 목표를 벗어난
  상태를 화면에 표시해야 한다** (5.2)
- 장면 역할 이름은 코드에 확정돼 있다 — `hook` / `question` / `countdown` / `answer` / `cta`

## 2. 앱 규격

| 항목 | 값 |
| --- | --- |
| 스택 | Electron + React (확정, PRD 14.1) |
| 대상 OS | Windows 11 기준. macOS는 미검증이므로 OS 고유 UI에 의존하지 말 것 |
| 기준 창 크기 | **1440 x 900** |
| 최소 창 크기 | **1280 x 720** — 이 크기에서 주요 화면이 깨지지 않아야 한다 |
| 리사이즈 | 창 크기 변경에 대응해야 한다. 모바일·태블릿 폭은 범위 밖 |
| 언어 | 한국어만. 다국어 전환 없음 |
| 테마 | **하나만 만든다.** 다크를 권장한다 — 프리뷰에 들어오는 D1 배경 3종이 전부 어두운 색이라 밝은 셸에서는 프리뷰만 검은 구멍처럼 보인다. 라이트를 제안하려면 근거와 함께 알려달라 |

> 위 창 크기는 발주 시점의 제안값이다. 시안 작업에 다른 기준이 낫다면 알려달라 —
> 정해진 제품 요구가 아니다.

## 3. 기술 제약 (가장 중요)

D1은 FFmpeg `drawtext`의 한계가 제약이었다. **D2는 React + CSS라 시각 표현 자체는 거의
자유롭다.** 대신 제약이 **속도**에 있다. 아래는 프로토타입 실측이다 (`docs/spikes/25-app-framework.md`).

### 3.1 영상 프리뷰는 재생되지 않는다 — 정지 프레임이다

**프레임마다 FFmpeg를 새로 띄우는 프리뷰는 성립하지 않는다.**

- 프리뷰 1프레임 생성에 **0.8~2.4초**가 걸린다
- 그 시간의 바닥이 **FFmpeg 프로세스 기동**이다 — 아무 일도 하지 않는 `ffmpeg -version`이
  이 머신에서 **1.1~1.3초**다 (같은 머신 `cmd /c ver`는 0.2초)
- 따라서 **해상도를 1/4로 낮춰도 빨라지지 않는다.** 화질을 포기해도 얻는 게 없다

**그래서 시안에 넣으면 안 되는 것:**

- ▶ 재생 버튼과 실시간 미리보기
- 드래그로 시각을 훑는 **타임라인 스크러버**
- 값을 바꾸는 즉시 프리뷰가 따라 바뀌는 **실시간 반영**

**대신 성립하는 것:** 장면을 선택하면 그 장면의 **대표 프레임 한 장**이 뜨는 방식. 프레임이
갱신되기까지 1~2초의 대기가 있으므로 **그 대기를 어떻게 보여줄지가 시안에 필요하다.**

> 프리뷰 갱신을 더 빠르게 만드는 방법(장면 대표 프레임 캐시 / 상주 프레임 서버 / 더 작은
> FFmpeg 빌드)은 구현 쪽에서 검토 중이지만, **어느 쪽을 골라도 실시간 재생은 되지 않는다.**
> 재생이 반드시 필요하다고 판단하면 시안에 넣기 전에 먼저 알려달라.

### 3.2 느린 동작과 빠른 동작의 경계가 명확하다

앱 ↔ Python 백엔드 왕복은 **0.2ms**(중앙값, 100회)다. **UI 지연 요인이 아니다.**
느린 것은 **FFmpeg를 부르는 두 가지뿐**이다.

| 동작 | 체감 | 화면에 필요한 것 |
| --- | --- | --- |
| 파일 열기·저장, 값 편집, 목록 재정렬 | 즉시 | 로딩 표시 불필요 |
| **프리뷰 프레임 생성** | 1~2초 | 대기 표시 |
| **최종 렌더** (1080x1920 H.264 인코딩) | 수십 초 | 진행률·취소·완료·실패 (5.5) |

즉 로딩 스피너가 필요한 자리는 두 곳뿐이고, 나머지는 즉각 반응해야 한다.

### 3.3 구현 불가 또는 고비용 — 쓰기 전에 상의할 것

- **오디오 파형(waveform) 표시** — 파형 이미지를 FFmpeg로 따로 구워야 해서 프리뷰와 같은
  비용이 붙는다. 꼭 필요하면 알려달라
- **타임라인 트랙 UI** (장면을 가로 막대로 늘렸다 줄이는 방식) — 편집 대상이 트랙이 아니라
  장면 목록이고, 길이 조정은 숫자 입력으로 충분하다. PRD 3장이 배제한 멀티트랙 편집기에 해당
- **오디오 재생과 화면 동기화** — 프리뷰가 정지 프레임이라 맞출 대상이 없다
- **네트워크가 필요한 모든 것** — 웹폰트 CDN, 원격 아이콘, 외부 이미지. 앱은 오프라인으로
  동작하며 **모든 에셋을 동봉해 배포한다**

## 4. 폰트와 시각 언어

### 4.1 폰트

- **재배포·임베딩 가능한 라이선스여야 한다.** 데스크톱 앱에 동봉해 배포한다
  (Windows 동봉 폰트는 재배포 불가라 쓸 수 없다 — D1과 같은 제약이다)
- **저장소에 이미 Pretendard가 번들돼 있다** (`assets/fonts/`, 웨이트 3종, D1에서 수령).
  **UI 폰트로 그대로 쓰면 추가 라이선스도 추가 용량도 없다.** 다른 폰트를 제안하려면 폰트
  파일과 라이선스 원문 링크를 함께 납품해달라
- 아이콘을 쓴다면 **아이콘 세트도 같은 라이선스 요건**을 따른다

### 4.2 프리뷰 안에 들어오는 D1 색

앱 화면 안의 9:16 프리뷰에는 아래 배경 위에 D1 자막 스타일이 얹힌 그림이 들어온다.
**앱 셸의 색이 이것들과 싸우지 않아야 한다.**

| 배경 프리셋 | 값 |
| --- | --- |
| `deep_navy` | 단색 `#101A33` |
| `purple_gradient` | 수직 `#1B0B2E` → `#4A1052` |
| `deep_teal_gradient` | 수직 `#06231F` → `#0B3A2C` |

자막 스타일 3종의 강조색은 `#FFE400`(임팩트 옐로) / `#35F5C0`(네온 민트) / `#FF7A45`(오렌지
카드)다. 전체 색표는 [D1 확정 스펙 6장](d1-video-design-spec.md)에 있다.

**앱의 강조색을 위 세 색 중 하나와 같게 쓰지 말 것을 권한다** — 프리뷰 안의 정답 강조와 앱
버튼이 같은 색이면 어느 쪽이 콘텐츠인지 구분되지 않는다.

### 4.3 명도비

본문 텍스트 대 배경 **4.5:1 이상**, 큰 텍스트·비활성 요소 **3:1 이상**을 지켜달라.
D1에서 이 값을 실측으로 검증했고(`tests/test_visual_assets.py`), D2에서도 같은 확인을 한다.
**상태를 색으로만 구분하지 말 것** — 특히 5.3의 `flagged` 표시는 색맹 사용자에게도 전달돼야
하므로 색 외의 신호(아이콘·문구)를 함께 둔다.

## 5. 화면별 필요 시안

### 5.1 S1 — 프로젝트 열기 (이슈 #26)

앱을 켜면 처음 보는 화면. **run 디렉터리를 골라 여는 것**이 유일한 시작점이다.

- 디렉터리 선택, (있다면) 최근 연 프로젝트 목록
- **프로젝트가 하나도 없는 빈 상태** — 처음 켠 사용자가 무엇을 해야 하는지 알아야 한다.
  영상 생성은 CLI에서 하므로 앱 안에 "새로 만들기"가 없다
- **여는 데 실패한 상태** — 형식에 맞지 않는 `project.json`을 열면 **원인이 표시되고 앱이
  죽지 않아야 한다**. 이건 완료 조건에 있는 요구다

### 5.2 S2 — 메인 편집 화면 (이슈 #27) ← **D2의 중심**

**앱 디자인의 첫 소비 지점이고, 나머지 세 화면이 이 골격 위에 얹힌다.**
이 화면이 확정돼야 #28·#29·#30이 각자 진행할 수 있다.

- **9:16 세로 캔버스 프리뷰** — 비율을 유지해야 한다. 3.1의 제약(정지 프레임, 1~2초 대기)
- **장면 목록**
  - `hook` / `question` / `countdown` / `answer` / `cta` **다섯 역할이 구분되어 보일 것**
  - **같은 문제의 세 장면(question·countdown·answer)이 하나의 그룹으로 묶여 보일 것** —
    사용자가 인식하는 단위는 장면이 아니라 문제다
  - 장면별 길이 표시
- **총 길이 표시와 목표 범위(45~60초) 이탈 표시** (1장 참고 — 실제 산출이 38초까지 내려간다)
- 장면을 고르면 프리뷰가 그 장면으로 이동

### 5.3 S3 — 문제 편집 (이슈 #28)

- 문제별 편집 폼: **질문 / 정답 / 해설 / 난이도(easy·medium·hard) / 카운트다운 길이(초)**
- 문제 추가·삭제·순서 변경
- **`flagged` 배지** — 자동 검증이 결함을 찾았거나 확신도가 낮은 문제. 사람이 반드시 확인해야
  하는 상태다. 함께 보여줄 근거는 **검증 사유 문구와 확신도 수치(0~1)** 두 가지다
  - 상태값은 셋이다: `verified`(검증이 결함을 못 찾음) / `flagged`(확인 필요) /
    `unverified`(검증 미완료 — 이것도 `flagged`로 취급된다)
- **"오디오·자막 재생성 필요" 표시** — 낭독되는 텍스트(질문·정답·해설)를 고치면 이미 만들어진
  음성과 자막이 낡은 상태가 된다. 사용자가 이걸 모르면 옛 음성이 든 영상을 내보낸다

> **`flagged` 표기는 5.5의 렌더 전 경고와 반드시 같은 시안에서 받아야 한다.**
> 같은 상태를 두 화면에서 다르게 그리면 사용자가 별개 문제로 오인한다.

### 5.4 S4 — 공통 편집 컨트롤 (이슈 #29)

- **자막 스타일 선택** — D1 프리셋 3종(임팩트 옐로 / 네온 민트 / 오렌지 카드)
- **배경 교체** — 프리셋 3종(4.2) 또는 사용자 파일(이미지·영상). 지원하지 않는 형식은
  **거부하고 이유를 표시**한다
  - 프리셋 조합에 **차단 대상이 없다.** 자막 스타일마다 권장 배경이 정해져 있으므로
    **기본 짝을 제시하되 다른 조합도 고를 수 있게** 한다
- 자막 텍스트 수정, 텍스트 오버레이 추가·수정·삭제
- 장면 순서 변경, **장면 길이 조정** — 낭독보다 짧게 줄이면 **경고가 표시돼야 한다**
- **볼륨 조정 — 낭독과 효과음 2종**. 배경음악은 이 범위에 없다 (별도 이슈)

> 이 이슈는 범위가 커서 구현 시 하위 이슈로 쪼갠다. 시안도 **컨트롤 하나짜리 화면**이 아니라
> 이 컨트롤들이 S2 골격 어디에 붙는지가 필요하다.

### 5.5 S5 — 렌더 실행 (이슈 #30)

**PRD 8장의 "업로드 전 사람이 검수한다"를 앱에서 완성하는 지점이다.**

- 렌더 진행 상황 — 수십 초 걸린다 (3.2)
- **`flagged` 문제가 있으면 렌더 전에 경고하고, 사용자가 명시적으로 확인하기 전에는 진행되지
  않는다.** 무심코 넘기게 만드는 표현이면 이 기능은 무력해진다
- 완료 — 출력 파일 위치 안내
- 실패 — 원인 표시와 재시도
- 업로드 관련 요소는 **넣지 않는다** (PRD 3장 비목표)

---

## 6. 상태 시안 — 정상 화면만으로는 성립하지 않는다

D1에서 "자막 스타일 프리셋 2개 이상"을 명시하지 않았다면 앱의 스타일 선택 기능 자체가
성립하지 않았을 것이다. **D2에서 같은 자리에 있는 것이 상태다.** 정상 화면만 받으면
아래 완료 조건을 채울 수 없다.

| 상태 | 어디에 |
| --- | --- |
| 빈 상태 (프로젝트 없음) | S1 |
| 열기 실패 (형식 오류 + 원인 표시) | S1 |
| **저장하지 않은 변경이 있음** | 전역 — 완료 조건이다 |
| 저장 실패 | 전역 — 실패해도 원본이 손상되지 않아야 한다 |
| 프리뷰 프레임 생성 중 (1~2초) | S2 |
| `flagged` 배지 / 경고 다이얼로그 | S3 · S5 (같은 시안) |
| 재생성 필요 (음성·자막이 낡음) | S3 |
| 입력값 오류 (형식 미지원, 길이가 낭독보다 짧음) | S4 |
| 렌더 진행 / 완료 / 실패 | S5 |

## 8. 납품 형식

**스택이 Electron + React로 확정돼 있어 CSS 값이 그대로 구현값이 된다.** D1은 CSS 시안을
FFmpeg 값으로 번역해야 해서 값이 어긋나는 지점이 있었지만(외곽선 두께가 두 배가 된 건이 대표),
**D2에는 그 번역 단계가 없다.**

- **HTML/CSS 프로토타입 또는 React 컴포넌트로 주는 것이 가장 좋다.** 값이 그대로 넘어온다
- Figma나 PNG로 준다면 **모든 수치를 텍스트로 병기**해달라 — 색 hex, 간격, 폰트 크기,
  최소 창 크기에서의 동작. 이미지만으로는 구현값을 특정할 수 없다
- 인터랙션은 영상이 아니라 **상태 → 상태 + 조건**으로 기술해달라
- 3장의 제약에 걸리는 표현을 쓰고 싶으면 **시안에 넣기 전에 먼저 알려달라**

## 10. 2차 배치 발주 — S4 잔여 (이슈 #29)

1차 배치에서 S4의 네 컨트롤(자막 스타일 · 배경 · 장면 길이 · 볼륨)이 S2 속성 패널에 함께
왔으므로, **2차에서 받을 것은 아래 셋뿐이다.** 나머지 편집 기능은 1차 시안으로 진행한다.

### 10.1 자막 텍스트 편집

장면에 그려지는 문구(`scenes.json`의 질문·정답·해설 텍스트)를 사람이 고치는 컨트롤이다.

- **낭독 텍스트를 고치는 것(S3)과 다른 동작이다.** S3은 콘텐츠(문제)를 고쳐 음성·자막이
  함께 낡지만, 여기서는 **자막만 고치고 음성은 그대로 둘 수 있다.** 두 경우가 화면에서
  구분돼야 한다 — 같은 "재생성 필요" 표시를 쓰면 사용자가 음성이 바뀐다고 오인한다
- 편집 자리는 S2 속성 패널의 **장면 구획**이다 (자막 스타일과 달리 장면마다 다른 값이다)

### 10.2 텍스트 오버레이 추가 · 수정 · 삭제

**저장소에 이 개념이 아직 없다.** `scenes.json`에도 `project.json`에도 오버레이 배열이 없어
시안이 제안하는 편집 속성이 그대로 스키마가 된다. 아래 제약 안에서 **무엇을 편집 대상으로
둘지 제안해달라.**

- **드래그로 위치를 잡는 UI는 성립하지 않는다.** 프리뷰가 정지 프레임이고 값을 고친 뒤 프레임
  갱신에 **2초대**가 걸린다(#27 실측 — 장면 이동만 3~5ms다). 드래그 중에는 결과가 보이지
  않으므로, 위치는 **이산 선택(예: 상·중·하 × 좌·중·우)이나 숫자 입력**이어야 한다
- **줄 하나가 `drawtext` 하나다.** 자유 폭 텍스트 상자가 없고 줄바꿈은 렌더러가
  `floor(840 / font_size)`로 계산한다 (D1 확정 스펙 7.3). 임의 크기의 박스에 텍스트를 흘리는
  표현은 구현 비용이 다르다 — 쓰고 싶으면 먼저 알려달라
- **폰트는 번들 Pretendard 3웨이트뿐이다** (4.1). 폰트 선택기를 그리지 말 것
- **색은 자막 스타일 프리셋 안에서 고르게 하는 쪽을 권한다.** 자유 색상 선택기를 두면 D1의
  프리셋 체계(확정 스펙 6장의 대비 매트릭스)를 사용자가 우회한다
- 표시 시각 범위를 어떻게 정할지도 필요하다 — 타임라인 스크러버는 3.1에서 배제됐으므로
  **장면 단위 또는 장면 시작 기준 초** 중 하나다

### 10.3 입력값 오류 상태 2종

확정 스펙 4장이 색의 뜻을 이미 갈라 뒀으므로(`danger` = 거부, `warn` = 경고이고 값은 적용된다)
**그 구분이 컨트롤에서 어떻게 보이는지**가 필요하다.

| 상태 | 색 | 확정된 동작 |
| --- | --- | --- |
| 지원하지 않는 배경 파일 형식 | `danger` | 받는 형식은 `.png` · `.jpg` · `.jpeg` · `.mp4`뿐이고 나머지는 **거부하며 이유를 표시**한다 (PRD 14.1) |
| 장면 길이가 낭독보다 짧다 | `warn` | **경고하되 값은 받는다.** 저장 위치는 `project.json`이다 (PRD 14.1) |

### 10.4 시안이 알아야 할 확정값

1차 배치 이후 저장소에서 닫힌 것들이다. **시안이 이것과 다르게 그리면 확정값이 이긴다.**

- **장면 순서 컨트롤을 두지 않는다.** #28의 문제 순서 변경이 곧 장면 순서 변경이고
  (`app/src/types/index.ts` — "순서가 곧 장면 순서다"), `hook`·`cta`는 위치가 고정이다
- **장면 길이 편집에서 `countdown`은 빠진다.** `duration`이 `seconds`와 같아야 하고 그 값은
  콘텐츠 필드라 S3의 카운트다운 초가 이미 소유한다
- **낭독 볼륨은 `project.json`에 새로 생기는 필드다.** 1차 시안의 0~100 슬라이더는 선형 게인에
  매핑되고 상한이 없다 (확정 스펙 5장) — 최종 오디오는 리미터가 -1 dBFS에서 잡는다
- 사람의 확인 기록은 `project.json`의 `review` 섹션이다 (확정 스펙 1.4가 지적한 계약 위반은
  #28에서 닫혔다)

### 10.5 발주하지 않는 것

| 화면 | 이유 |
| --- | --- |
| S1 프로젝트 열기 | #26이 토큰·인벤토리로 조립해 이미 동작한다 (`app/src/components/OpenScreen.tsx`). 지금 받으면 머지된 화면을 다시 손대는 비용뿐이다 — 최근 목록처럼 없는 기능이 필요해지면 그때 따로 발주한다 |
| S5 렌더 | 1차에서 수령 완료 (확정 스펙 3.3) |

### 10.6 마감

**#29의 자막 텍스트·오버레이 하위 이슈 착수 전.** 나머지 하위 이슈(자막 스타일·배경 프리셋,
배경 사용자 파일, 볼륨, 장면 길이)는 1차 시안으로 진행하므로 **이 배치를 기다리지 않는다.**
