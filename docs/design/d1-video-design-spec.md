# D1 영상 디자인 — 확정 구현 스펙

수령한 D1 시안을 **이 저장소의 확정값과 대조해 정리한 결과**다. 발주 문서는
[`d1-video-design-brief.md`](d1-video-design-brief.md)이고, 원본 시안은
[Claude Design 프로젝트](https://claude.ai/design/p/26611470-26f3-4d73-9faf-4fff2acf1743)의
`D1 Video Design Spec.dc.html`에 있다.

**원본 시안과 이 문서가 다르면 이 문서가 이긴다.** 시안은 CSS로 그려졌고 렌더는 FFmpeg
`drawtext`라서, 같은 숫자가 같은 그림을 만들지 않는 지점이 있다 (2장). 시안 자체의 계산
오류도 여기서 고쳤다 (7장).

렌더는 아직 구현되지 않았다. 이 문서의 수치는 #20~#22의 **입력**이고, 2장의 세 항목은
실측 전까지 확정이 아니다.

---

## 1. 좌표계와 캔버스

| 항목 | 값 |
| --- | --- |
| 캔버스 | 1080 × 1920 / 30fps |
| 안전 영역 | 상 260 / 하 420 / 우 160 / 좌 80 |
| 텍스트 컬럼 | x 80 → 920 (width 840) |
| 정렬 중심 | **x = 500** (캔버스 중앙 540이 아니다 — 우측 160px가 Shorts 사이드 버튼 영역이다) |
| 사용 가능 y | 260 → 1500 |

- 가로 중앙 정렬은 `x=(500-text_w/2)`.
- **줄바꿈은 렌더 전에 파이썬이 계산해 `\n`을 넣는다.** `drawtext`에 자동 줄바꿈이 없다.
- 줄당 최대 글자 수는 `floor(840 / font_size)`로 잡는다. 한글 1자 ≈ 1.0em 가정이며
  숫자·영문이 섞이면 실제보다 보수적이다 (7.3).

---

## 2. 실측 전까지 확정이 아닌 것

세 항목은 **수치가 아니라 가정**이다. 실측 결과에 따라 값이나 방식이 바뀐다.

### 2.1 외곽선 두께 — 시안 값의 절반에서 시작한다 (#20)

시안은 CSS `-webkit-text-stroke` + `paint-order: stroke fill`이다. 이 조합은 외곽선을
글리프 경로 **중심 기준**으로 그리고 안쪽 절반을 채움색이 덮으므로, **눈에 보이는 두께는
지정값의 절반**이다. FFmpeg `borderw=N`은 N픽셀 전부 바깥으로 그린다.

따라서 시안의 `stroke: 8px`을 `borderw=8`로 옮기면 두 배로 두꺼워진다.

| 시안 stroke | 구현 `borderw` |
| --- | --- |
| 5px | 3 |
| 6px | 3 |
| 8px | 4 |
| 10px | 5 |
| 12px | 6 |
| 14px | 7 |

이 디자인은 외곽선이 지배적인 시각 요소라 위 값은 **출발점**이고, #20에서 실제 렌더를
보고 맞춘다.

### 2.2 확대 중 중앙 정렬 (#22)

이 저장소에서 확인된 것은 `fontsize`가 시간 표현식을 받는다는 것까지다. 정답 확대는
`fontsize`가 79→132로 변하는데, 중심을 고정하려면 `x=(500-text_w/2)` / `y=(1112-text_h/2)`의
`text_w`·`text_h`가 **매 프레임 갱신돼야** 한다. 갱신되지 않으면 글자가 중앙이 아니라
좌상단 고정점에서 오른쪽·아래로 자란다.

**#22의 첫 실측 항목이다.** 갱신되지 않으면 각 티어의 최종 크기로 좌표를 미리 계산해
고정하는 방식으로 바꾼다 (확대 중 중심이 약간 흔들리는 것을 감수).

### 2.3 카운트다운 진행 바 (#21)

`drawbox`의 `w`를 시간 표현식으로 제어할 수 있다는 가정 위에 있다. 실측하지 않았다.
**#21의 첫 검증 항목이고, 실패하면 바만 제거한다** — 다른 수치는 영향받지 않는다.

### 2.4 줄 간격 (#20)

`line_spacing`은 줄 사이의 **추가** 간격이고 기준 행높이는 폰트 메트릭에서 나온다.
아래 표의 `LH` 값을 `line_spacing`으로 그대로 옮길 수 없다. Pretendard로 실측해 역산한다.

## 3. 장면 길이 — 저장소 확정값을 시안에 맞춘다

시안이 저장소의 고정 길이와 달랐고, **시안 쪽으로 통일했다.** 프레임 레이아웃이 그 길이를
전제로 검증됐고, 총 길이 예산에 여유가 생긴다.

| 장면 | 변경 전 | **확정** | 위치 |
| --- | --- | --- | --- |
| `hook` | 3.0초 | **2.5초** | `scene_template.HOOK_DURATION` |
| `cta` | 4.0초 | **3.0초** | `scene_template.CTA_DURATION` |
| `countdown` | 4초 | **3초** | `config.quiz.countdown_sec` 기본값 |
| `question` / `answer` | 실측 | 실측 (변경 없음) | PRD 7.5.1 |

`countdown_sec` 3은 시안의 3 → 2 → 1 (각 1.0초)과 대응한다. 4로 두면 렌더러가
4 → 3 → 2 → 1을 그리게 되는데 시안이 검증하지 않은 배치다. **`countdown_sec`는 여전히
설정값이므로 4로 올리면 4자리가 나온다** — 렌더러는 `seconds` 값만큼 센다.

새 예산 (스파이크 #2 4.3의 실측 중앙값, 4문제):

```text
hook 2.5 + question 4.3×4 + countdown 3.0×4 + answer 3.0×4 + cta 3.0 = 46.7초
```

PRD 6.3의 45~60초 안이고, 이전 계산(52.2초)보다 5.5초 여유가 생긴다. 해설이 긴 문제에
읽기 하한(4장)이 걸릴 때 쓸 여유다.

## 4. 해설 등장 시각과 읽기 하한

시안은 해설을 **정답 장면 시작 기준 0.90초**에 띄운다. 이 값이 #16의 자막 읽기 하한과
맞물린다 — 하한의 앞항이 `lead_in`(0.30)이 아니라 이 값이어야 실제로 읽을 시간이 보장된다.

```text
duration = max(
    lead_in + audio_duration + tail,
    min_duration,
    caption_onset + len(caption) / reading_cps + tail    # caption이 있는 장면만
)
```

| config 키 | 값 | 소비 |
| --- | --- | --- |
| `timing.caption_onset_sec` | 0.90 | #16(하한 계산), #22(해설 표시 시점) — **같은 값을 읽는다** |
| `timing.reading_cps` | 12.0 | #16 |

해설 60자(`quiz.explanation_max_len` 상한)면 정답 장면이 `0.90 + 5.0 + 0.5 = 6.4초`가 된다.
4문제가 전부 상한이면 총합이 60초를 넘어 경고가 걸리는데, **그것이 그 경고의 용도다**
(PRD 7.5.1, 6.3). 렌더는 막지 않는다.

## 5. 장면별 구현 수치

색은 프리셋이 정한다 (6장). 아래는 **P1 임팩트 옐로** 기준이며 좌표·크기·줄 수는 프리셋
3종이 공통이다.

`borderw` 열은 2.1의 환산값이다. `shadow`는 `shadowx=0:shadowy=N:shadowcolor=black@A`.

### 5.1 hook (2.5초, 애니메이션 없음)

| 요소 | y | 크기 | 웨이트 | 색 | borderw | shadow | 출처 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| kicker | 520 | 44px | 800 | 강조색 | 3 | 없음 | `scenes[0].kicker` |
| hook | 760 | 76px / LH104 | 800 | 본문색 | 4 | +8 @0.5 | `scenes[0].text` |
| meta | 1060 | 40px | 700 | 보조색 | 3 | 없음 | 렌더러가 계산 |

- hook 텍스트 티어: **≤22자** → 76px / LH104 / 2줄 (11자/줄) · **23–36자** → 64px / LH88 /
  3줄 (13자/줄). 36자 초과는 생성 단계에서 막는다 (8장).
- meta는 `scenes.json`에서 파생한다 — `문제 {고유 question_id 수}개 · {duration 합 반올림}초`.
  타입 전용 산출물을 열지 않으므로 경계 위반이 아니다 (PRD 7.4.1).

### 5.2 question (실측 길이, 애니메이션 없음)

| 요소 | y | 크기 | 웨이트 | 색 | borderw | shadow |
| --- | --- | --- | --- | --- | --- | --- |
| index | 400 | 48px | 800 | 강조색 | 3 | 없음 |
| question | 648 (**상단 고정**) | 64px / LH88 | 700 | 본문색 | 4 | +6 @0.45 |

- **상단 정렬이다.** 줄 수가 변해도 첫 줄 위치가 안 움직인다. 3줄 기준 점유 y648–912.
- 티어: **≤39자** → 64px / LH88 / 3줄 (13자/줄) · **40–45자** → 56px / LH78 / 3줄
  (15자/줄), y664. 45자 초과는 생성 단계에서 막는다 (8장).
- index 문구는 `Q{question_id} / {총 문제 수}`. 둘 다 `scenes.json`에서 나온다.

### 5.3 countdown (`seconds`초)

| 요소 | y | 크기 | 웨이트 | 색 | borderw | shadow |
| --- | --- | --- | --- | --- | --- | --- |
| index · question | 5.2와 **완전 동일** | | | | | |
| digit | 박스 1060 h240 | 240px | 800 | 강조색 | 7 | +12 @0.5 |
| bar (2.3) | 1330 h14, x80 w840 | — | — | 트랙 흰색@0.16 / 채움 강조색 | — | — |

- **질문은 `drawtext` 인스턴스 하나가 question + countdown 두 장면을 덮는다.** 좌표·크기·색이
  같아야 성립하므로 축소·이동을 넣지 않는다.
- digit은 `seconds`부터 1까지 각 1.0초, 전환 애니메이션 없음, 크기 고정(펄스 없음).
- bar 채움폭 `840 * (1 - t/T)` 좌→우 감소.

### 5.4 answer (실측 길이)

정답 박스는 **y1000 h224 고정**, 중심 (500, 1112). 티어와 무관하게 박스 높이가 같아서
해설 y1300은 어떤 경우에도 안전하다.

| 요소 | y | 크기 | 웨이트 | borderw | shadow |
| --- | --- | --- | --- | --- | --- |
| index · question | 5.2와 좌표 동일, **감쇠색으로 교체** | | | | |
| 정답 T1 (1–6자) | 박스 중앙 | 79 → 132px, 1줄 | 800 | 5 | +10 @0.5 |
| 정답 T2 (7–20자) | 박스 중앙 | 50 → 84px, 최대 2줄 (10자/줄) / LH112 | 800 | 5 | +10 @0.5 |
| 해설 | 1300 (**고정**) | 36px / LH52, 최대 3줄 (23자/줄) | 500 | 3 | 없음 |

T2 상한 20자는 `config.quiz.answer_max_len`과 일치한다. 해설 상한 60자는
`quiz.explanation_max_len`과 일치하고 3줄 × 23자 = 69자 안에 들어간다. 정답 박스 하단
1224 ↔ 해설 상단 1300 = **간격 76px**.

**타임라인** (장면 시작 기준 초):

| t | 정답 | 그 밖 |
| --- | --- | --- |
| 0.00 | 미표시 | 질문·index를 감쇠색으로 교체 |
| 0.15 | 시작 크기, 본문색으로 등장 | **효과음 트리거 (#23)** |
| 0.15 → 0.50 | 시작 → 목표 크기 선형 확대 | 0.35 지점에서 강조색으로 1프레임 전환 |
| 0.50 | 목표 크기 고정 | — |
| 0.90 | — | 해설 표시 (페이드 없음) |
| 장면 끝 | — | 낭독 종료 + `tail` |

### 5.5 cta (3.0초, 애니메이션 없음)

| 요소 | y | 크기 | 웨이트 | 색 | borderw | shadow | 출처 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| line1 | 700 | 68px / LH96 | 800 | 본문색 | 4 | +8 @0.5 | `scenes[-1].text` |
| punch | 980 | 88px | 800 | 강조색 | 5 | +10 @0.5 | `render.cta_punch` |
| tail | 1180 | 40px | 700 | 보조색 | 3 | 없음 | `render.cta_tail` |

- line1은 LLM이 생성하는 유일한 줄이다. 최대 2줄 (12자/줄, ≤24자).
- **punch와 tail은 채널 브랜딩이라 config로 뺐다.** 기본값 `구독 · 좋아요` / `매일 새 상식 퀴즈`.
  타입 전용 정보가 아니므로 `scenes.json`에도 `quiz.json`에도 넣지 않는다. 채널마다 바꾸는
  값을 LLM이 매번 새로 짓게 하는 것도 맞지 않는다.
- punch 1줄 9자, tail 1줄 21자. 초과하면 렌더 시작 전에 오류 (설정값이므로 사람의 오타다).

## 6. 프리셋

**값은 `assets/`에 커밋돼 있다** (#38). 아래 표가 설명하는 것이고, 코드가 읽는 것은
`assets/caption-styles/presets.json`과 `assets/backgrounds/presets.json`이다 — 조회는
`shorts_maker.assets`의 `caption_styles()` / `background_presets()` 하나씩이고, 설정 키
`render.caption_style` / `render.background`가 이름을 받는다. 색을 고칠 때는 그 파일을 고치고
이 표를 함께 갱신한다.

### 6.1 자막 스타일 3종 — 색만 바꾼다

**좌표·크기·줄 수는 3종이 공통이다.** 프리셋 교체로 레이아웃이 회귀하지 않는다.

| 역할 | P1 임팩트 옐로 | P2 네온 민트 | P3 오렌지 카드 |
| --- | --- | --- | --- |
| 본문색 (질문·hook·cta line1) | `#FFFFFF` | `#F2FFFB` | `#EAF7F1` |
| 감쇠색 (answer 중 질문·index) | `#7C87A3` | `#9B8AAE` | `#7E9A8E` |
| 강조색 (확정 정답·digit·punch·kicker·index) | `#FFE400` | `#35F5C0` | `#FF7A45` |
| 정답 등장 시 | `#FFFFFF` | `#F2FFFB` | `#FFFFFF` |
| 보조색 (해설·meta·tail) | `#DCE3F2` | `#F2FFFB` | `#EAF7F1` |
| 외곽선색 | `#0A0F1E` | `#10041C` | `#02120F` (정답만 `#2B0B0B`) |
| 그림자 | 있음 @0.5 | **없음** (외곽선 +1 두껍게) | 있음 @0.55 |

P2는 그림자 대신 두꺼운 외곽선을 쓴다 — 5장의 `borderw`에서 질문 4→4, 정답 5→6, 해설 3→3.
정답 하나만 바뀌므로 프리셋이 담는 값은 `answer_border_bonus` 하나다.

시안 원본은 P3를 "레드 카드"로 불렀으나 정답색이 오렌지라 **오렌지 카드**로 고쳤다.

프리셋 이름은 `impact_yellow` / `neon_mint` / `orange_card`다. 설정 파일과 `project.json`에
사람이 적는 값이라 `p1` 같은 번호를 쓰지 않았다 — 번호는 무엇이 바뀌는지 알려주지 않는다.

### 6.2 배경 3종

| 이름 | 프리셋 이름 | 값 |
| --- | --- | --- |
| B1 딥 네이비 | `deep_navy` | 단색 `#101A33` |
| B2 퍼플 그라디언트 | `purple_gradient` | 수직 `#1B0B2E`(y0) → `#4A1052`(y1920) |
| B3 딥 틸 그라디언트 | `deep_teal_gradient` | 수직 `#06231F`(y0) → `#0B3A2C`(y1920) |

수직 2스톱뿐이다. 이미지 배경·노이즈·비네트 없음. **종류를 따로 적지 않는다** — 스톱이 1개면
단색, 2개면 수직 그라디언트다.

FFmpeg `gradients` 필터가 두 스톱을 정확히 재현하는 것이 확인됐다 (#38) — PNG를 미리 구울
필요가 없다. **`y1`은 1919(높이-1)여야 한다.** 1920을 주면 프레임 범위를 벗어난 값이라 필터가
자기 기본 동작(시간에 따라 회전하는 그라디언트 선)으로 조용히 되돌아가고, 램프가 y703에서
끝나 아래쪽 63%가 단색이 된다. 오류도 경고도 나지 않으므로 눈으로만 잡히는 종류다.

```text
gradients=s=1080x1920:c0=0x1B0B2E:c1=0x4A1052:x0=0:y0=0:x1=0:y1=1919
```

이 명령의 실측 — y0 `#1B0B2E`, y480·y960·y1440이 선형 보간값, y1919 `#4A1052`, 같은 행에서
x 방향 변화 없음.

### 6.3 조합 매트릭스 — 차단 대상 없음

| | B1 네이비 | B2 퍼플 | B3 틸 |
| --- | --- | --- | --- |
| P1 옐로 | ◎ 기본 | ◎ | ○ |
| P2 민트 | ◎ | ◎ 기본 | △ 색상 단조 |
| P3 오렌지 | ○ | △ 탁함 | ◎ 기본 |

◎ 권장 · ○ 사용 가능 · △ 대비는 통과하나 권장하지 않음. **앱(#29)은 조합을 막을 필요가
없고**, 프리셋 선택 시 ◎ 배경을 기본값으로 짝지어 주기만 하면 된다. 그 짝은
`assets/caption-styles/presets.json`의 `background`에 들어 있다.

#### 명도비 — "9조합 전부 7:1 이상"은 사실이 아니었다

이 절은 원래 9조합 전부 정답색(강조색) 대 배경 명도비가 7:1을 넘는다고 적었다. #38에서
커밋할 색값으로 WCAG 2.1 상대 휘도를 계산한 결과 **P3 오렌지가 세 배경 모두에서 7:1을 넘지
못한다.** 색을 바꾸는 대신 주장을 실측으로 고쳤다 — 시안이 P3×B3을 ◎ 기본으로 판정했고,
번인 텍스트는 전부 36px 이상이라 WCAG의 **대형 텍스트** 기준(AA 3:1 / AAA 4.5:1)이 적용된다.

강조색 대 배경(그라디언트는 밝은 쪽 스톱, 즉 최악의 값):

| | B1 네이비 | B2 퍼플 | B3 틸 |
| --- | --- | --- | --- |
| P1 옐로 `#FFE400` | 13.43 | 10.99 | 9.87 |
| P2 민트 `#35F5C0` | 12.30 | 10.07 | 9.04 |
| P3 오렌지 `#FF7A45` | 6.67 | 5.46 | **4.90** |

- 성립하는 하한은 두 개다. **모든 색(본문·감쇠·강조·정답 등장·보조) × 9조합에서 3:1 이상**
  이고(최저 3.53 — P1 감쇠색 `#7C87A3` × B3), **◎ 기본 짝에서는 강조색·본문색이 4.5:1 이상**
  이다(최저 4.90 — 위 표의 P3×B3).
- 감쇠색이 가장 낮은 것은 의도한 결과다. 정답 장면에서 질문을 죽이는 색이므로 대비가 낮아야
  하고, 그래도 3:1 위에 있다.
- 이 계산은 `tests/test_visual_assets.py`가 커밋된 색값에서 매번 다시 한다. 색을 고치면 위
  하한을 넘는지 그 테스트가 확인한다.

## 7. 시안에서 고친 것

| 항목 | 시안 | 확정 | 이유 |
| --- | --- | --- | --- |
| 외곽선 두께 | stroke 5~14px | `borderw` 3~7 | 2.1 — CSS stroke는 절반만 보인다 |
| 질문 하위 티어 | 40–48자 | **40–45자** | `floor(840/56) = 15`, 3줄이면 45자가 상한이다. 48자는 4줄이 된다 |
| kicker·index 자간 | `letter-spacing` 0.06~0.1em | **0** | `drawtext`에 자간 파라미터가 없다 (발주서 3장이 "구현 불가"로 명시한 항목) |
| hook 그림자 불투명도 | 본문 45% / CSS 50% | **50%** | 시안 안에서 값이 갈렸다. 다른 요소와 일관되게 50% |
| P3 이름 | 레드 카드 | **오렌지 카드** | 정답색이 `#FF7A45`다 |
| 장면 길이 | hook 2.5 / cta 3.0 / cd 3.0 | 동일 (저장소 쪽을 바꿈) | 3장 |

### 7.3 줄바꿈 공식의 한계

`floor(840 / font_size)`는 한글 1자 = 1.0em 가정이다. 숫자·영문·기호는 실제로 절반 폭이라
`지구 표면의 약 71%를`(11자) 같은 문장은 계산보다 훨씬 짧게 렌더된다. **넘침 방향으로는
안전하지만 시안보다 이르게 줄이 바뀐다.**

정확히 하려면 폰트 메트릭으로 실제 폭을 재야 하고 의존성이 하나 늘어난다. MVP는 공식으로
가고, #20에서 실제 렌더를 보고 판단한다.

## 8. 이 스펙이 요구하는 저장소 변경

시안이 `scenes.json`에 없는 텍스트를 요구한다. 어디서 채울지는 아래로 정리했다.

| 시안 요소 | 조달 방법 |
| --- | --- |
| countdown·answer 장면의 질문 | **`scenes.json`에 `heading` 통과 필드 신설.** 장면 템플릿이 question·countdown·answer 세 장면에 같은 값을 넣는다 |
| hook의 kicker `상식 퀴즈` | **`scenes.json`에 `kicker` 통과 필드 신설.** 장면 템플릿이 `quiz.json`의 `category`를 한국어 라벨로 옮긴다 |
| hook의 meta `문제 4개 · 48초` | 렌더러가 `scenes.json`에서 계산. 스키마 변경 없음 |
| 문제 인덱스 `Q2 / 4` | 렌더러가 `question_id`와 고유 개수로 계산. 스키마 변경 없음 |
| cta punch · tail | `render.cta_punch` / `render.cta_tail` 설정 (5.5) |
| 텍스트 길이 상한 | `quiz.hook_max_len` 36 / `quiz.question_max_len` 45 / `quiz.cta_max_len` 24 신설, 생성 단계에서 강제 |

`heading`은 question 장면에도 넣는다. 그 장면에서는 `text`와 값이 같아 중복이지만, 렌더러
규칙이 **"`heading`이 있으면 y648에 그린다"** 하나로 끝난다. answer 장면에서는 `text`가
정답이고 `heading`이 질문이라 두 필드가 반드시 갈라져야 하므로, 규칙을 하나로 두는 편이
싸다. 이름을 `question_text`로 하지 않은 것은 `explanation`을 `caption`으로 옮긴 것과 같은
이유다 — 통과 필드는 타입 중립 어휘를 쓴다 (퀴즈 스펙 1.1).

신설 config 키 정리:

```yaml
timing:
  caption_onset_sec: 0.90
  reading_cps: 12.0
quiz:
  countdown_sec: 3        # 4에서 변경
  hook_max_len: 36
  question_max_len: 45
  cta_max_len: 24
render:
  cta_punch: "구독 · 좋아요"
  cta_tail: "매일 새 상식 퀴즈"
  background: deep_navy         # 6.2의 프리셋 이름 (#38)
  caption_style: impact_yellow  # 6.1의 프리셋 이름 (#38)
```

`background`·`caption_style`은 프리셋을 저장소에 들인 #38에서 함께 열렸다. 기본값이 6.3의
◎ 기본 짝이고, 없는 이름을 적으면 실행 시작 시점에 쓸 수 있는 이름을 나열하며 멈춘다.

## 9. 폰트 — `assets/fonts/` (#38에서 반영 완료)

| 파일 | 웨이트 | 사용처 |
| --- | --- | --- |
| `Pretendard-ExtraBold.otf` | 800 | 정답, 카운트다운 숫자, hook, cta punch, index |
| `Pretendard-Bold.otf` | 700 | 질문, kicker, meta, cta tail |
| `Pretendard-Medium.otf` | 500 | 해설 자막 |
| `OFL.txt` | — | 라이선스 원문. 폰트와 같은 디렉터리에 동봉 |

- **변수 폰트 파일은 쓰지 않는다.** `drawtext`가 웨이트를 선택할 수 없어 파일 1개 = 웨이트 1개다.
  Pretendard 1.3.9 릴리스의 정적 파일을 받는다.
- **확장자가 `.ttf`가 아니라 `.otf`다.** 이 표는 원래 `.ttf`로 적었지만 릴리스의 기본 정적
  세트가 `public/static/*.otf`이고 `.ttf`는 `alternative/`에 있다. 두 세트는 `name` 테이블·
  `usWeightClass`·`fsType`·수직 메트릭·`unitsPerEm`·한글 커버리지가 모두 같고 `drawtext`
  렌더도 같아서, 웨이트 3개에서 3.3MB가 작은 쪽을 골랐다. 대조 결과는
  `assets/fonts/CREDITS.md`에 있다. **2.4의 `line_spacing` 역산은 영향받지 않는다** —
  메트릭이 동일하다 (`hhea` 1950 / -494 / 0, upem 2048).
- SIL Open Font License 1.1 — 임베딩·동봉 재배포·수정 허용. 한국어 음절 11,172자 전체 포함
  (커밋된 파일에서 확인, `tests/test_visual_assets.py`).
- 출처: https://github.com/orioncactus/pretendard
- 조회는 `shorts_maker.assets.font_path(weight)` 하나다. `render.font_path` 설정으로 사용자
  폰트를 지정했을 때의 선택 규칙은 렌더러(#20)가 정한다.
