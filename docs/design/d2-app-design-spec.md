## 1. 시안에서 고친 것

### 1.1 자막 스타일과 배경의 권장 짝 — 둘이 서로 바뀌어 있다

시안의 스타일 카드는 각 프리셋 옆에 권장 배경을 적어 두는데, **세 개 중 두 개가 틀렸다.**

| 프리셋 | 시안이 적은 배경 | **확정값** |
| --- | --- | --- |
| `impact_yellow` | `deep_navy` | `deep_navy` ○ |
| `neon_mint` | `deep_teal` | **`purple_gradient`** ✕ |
| `orange_card` | `purple` | **`deep_teal_gradient`** ✕ |

민트와 오렌지의 짝이 맞바뀌었다. 확정값은 `assets/caption-styles/presets.json`의
`background` 필드이고, D1 확정 스펙 6.3의 조합 매트릭스에서 ◎ 기본으로 판정된 짝이다.

**단순한 표기 실수가 아니라 대비가 나쁜 쪽을 기본값으로 만든다.** 시안이 제시한 두 조합은
그 매트릭스에서 △(권장하지 않음)다 — P2 민트 × B3 틸은 색상이 단조롭고, P3 오렌지 × B2
퍼플은 탁하다. 앱이 스타일을 고를 때 배경을 함께 바꿔 주는 동작(시안 `pickStyle`)이 있으므로,
이 값을 그대로 옮기면 사용자가 스타일을 고르는 것만으로 권장하지 않는 조합에 들어간다.

조합 자체를 막지는 않는다 — 매트릭스에 차단 대상이 없다. 기본 짝만 바로잡는다.

### 1.2 고정 장면 길이 — hook 3.0 / cta 3.5는 옛 값이다

시안 스크립트의 `HOOK_DUR = 3.0, CTA_DUR = 3.5`는 확정값과 다르다.

| 장면 | 시안 | **확정값** |
| --- | --- | --- |
| `hook` | 3.0초 | **2.5초** |
| `cta` | 3.5초 | **3.0초** |
| `countdown` | 3초 | 3초 ○ (`quiz.countdown_sec` 기본값) |

D1 확정 스펙 3장에서 시안에 맞춰 짧아진 값이고 PRD 7.5.1·퀴즈 스펙 2장이 같은 값을 쓴다.
시안의 총 길이 표시(48.1초)는 이 두 값 때문에 1.0초 길게 나온 것이다.

### 1.3 산출물 경로와 파일명 — 세 자리가 틀렸다

시안이 화면에 그린 문자열이 실제 산출물 규격(PRD 6.2)과 다르다. 화면에 그대로 노출되는
값이라 옮겨 적으면 사용자가 없는 경로를 찾게 된다.

| 위치 | 시안 | **확정값** |
| --- | --- | --- |
| 헤더 프로젝트 경로 | `runs/2026-08-11_143022` | `outputs/run-{timestamp}/` |
| 렌더 완료 출력 | `runs/…/out/final.mp4` | `final_short.mp4` (run 디렉터리 **루트**) |
| 렌더 실패 로그 | `audio/answer_02.wav` | `audio/seg-003.mp3` |

세 번째가 특히 중요하다. 세그먼트 파일명은 **역할 이름이 아니라 장면 배열 인덱스**로 매기고
확장자는 mp3다 (`segment_path(scene_index)`, PRD 7.5.2). 앱이 오디오 파일을 가리키는 모든
문구가 이 규칙을 따라야 하며, 낭독이 없는 장면에는 번호가 비어 있다.

### 1.4 "확인함으로 표시"가 `verify.status`를 덮어쓰면 안 된다 — 계약 위반

시안 S3의 `resolveFlag`는 사람이 확인 버튼을 누르면 해당 문제의 `status`를 `verified`로,
`confidence`를 `1`로 바꾼다. **이 동작은 그대로 구현할 수 없다.**

- `verify.status`는 **"정답이 맞다"가 아니라 "검증 단계가 결함을 찾지 못했다"**는 뜻이고,
  값을 산출하는 것은 `quiz_verifier`(#10), 임계값을 적용해 확정하는 것은
  `quiz_review.py`(#11)다. 사람의 판단과 검증기의 산출이 같은 칸을 공유하면 그 칸이 무엇을
  뜻하는지 알 수 없게 된다
- `confidence`는 검증기가 계산한 수치다. 사람이 `1`을 써 넣으면 임계값 판정(`< 0.8`이면
  `flagged`)이 **다음 실행에서 조용히 통과**한다
- `quiz.json`의 `verify`는 스키마에 `status` / `confidence` / `source` 셋뿐이고
  (`schemas/quiz.py`), 사람 확인을 기록할 칸이 없다

**확정 동작** — 사람 확인은 `verify`를 건드리지 않고 별도 자리에 기록한다. 어느 파일의 어느
필드인지는 6장의 남은 결정이다. 화면 쪽은 시안 그대로 두면 된다: 배지가 `verified`로 바뀌는
것이 아니라 **"확인함" 표시가 추가로 붙고**, S5의 경고 목록에서 빠진다.

### 1.5 자막 스타일과 배경은 장면 속성이 아니다

시안은 우측 패널 머리에 선택된 장면의 역할(`selectedRole`)을 띄우고, 그 아래에 자막
스타일·배경·장면 길이·볼륨을 차례로 놓았다. 그런데 이 넷 중 **자막 스타일·배경·볼륨은
프로젝트 전역 값**이고(`project.json`의 `render.caption_style` / `background` / `audio`),
장면별로 다를 수 있는 것은 길이 하나뿐이다.

패널 머리의 역할 표시 바로 아래에 전역 설정이 오면 "이 장면의 자막 스타일"로 읽힌다.
**확정** — 속성 패널을 두 구획으로 나누고 경계를 시각적으로 드러낸다. 위쪽이 선택된 장면에
적용되는 값(길이), 아래쪽이 프로젝트 전체에 적용되는 값(자막 스타일·배경·볼륨)이며,
아래 구획에는 전역임을 알리는 머리글을 둔다. 색과 컴포넌트는 시안 그대로다.

### 1.6 폰트는 CDN이 아니라 번들에서 온다

시안 `<helmet>`이 Pretendard를 `cdn.jsdelivr.net`에서 불러온다. 앱은 오프라인으로 동작하고
네트워크 호출이 없다(브리프 3.3). **구현은 `assets/fonts/`의 번들 폰트를 쓴다** — D1에서
받아 `assets/fonts/Pretendard-*.otf`로 커밋된 웨이트 3종이고 조회는 `assets.font_path(weight)`
하나다. 시안의 CDN 링크는 미리보기를 위한 것이며 옮기지 않는다.

아이콘도 같다. Lucide(ISC, 재배포 가능) 16px / 스트로크 1.5px를 **동봉**하고, 시안의
`!` · `✓` · `×` · `↻` 자리에 각각 `alert-triangle` · `check` · `x` · `refresh-cw`가 들어간다.

### 1.7 `text/3` 토큰의 명도비가 소형 텍스트 기준에 못 미친다

시안이 토큰 페이지에 적은 명도비 세 건을 커밋할 색값으로 다시 계산했다. **주장 자체는 전부
실제보다 보수적이라 문제가 없다** — D1의 "9조합 전부 7:1"과 달리 과장이 아니다.

| 조합 | 시안 주장 | 실측 |
| --- | --- | --- |
| 본문 `#E8EAED` on `#0E0F12` | 15.1:1 | **15.90:1** |
| 보조 `#A2A8B4` on `#15171B` | 7.4:1 | 7.52:1 |
| 비활성 `#6E7480` on `#15171B` | 3.6:1 | 3.82:1 |

문제는 시안이 적지 않은 쪽이다. **`text/3`(`#6E7480`)은 11px `caption` 토큰의 색이기도
한데**, 그 크기는 WCAG의 대형 텍스트가 아니라 **소형 텍스트라 AA 기준이 4.5:1**이다.

- `#6E7480` on `#0E0F12` (창 바탕) = **4.08:1** — 미달
- `#6E7480` on `#15171B` (카드·입력) = **3.82:1** — 미달

**확정** — `text/3`을 비활성 상태와 아이콘·구분 기호에만 쓰고, **읽어야 하는 11px 문구에는
`text/2`(`#A2A8B4`)를 쓴다**(같은 배경에서 7.7:1 / 7.5:1). 시안에서 이 교체가 필요한 자리는
장면 목록의 역할 이름, 총 길이 눈금, 프리뷰 하단 캡션, 각 패널의 보조 설명이다. 색표 자체는
바꾸지 않는다 — 쓰이는 자리를 좁힌다.

D1 확정 스펙 6.3과 같은 방식으로 `tests/`가 커밋된 색값에서 이 계산을 다시 하도록 둔다.

### 1.8 목표 범위 경고는 3문제 구성에서 상시 켜진다

시안의 총 길이 경고는 `total < 45 || total > 60`이고 문구가 "문제를 추가하거나 장면 길이를
늘려야 한다"이다. 그런데 **3문제 구성은 정상 산출인데도 총 길이가 38초대로 나온다**
(브리프 1장 — 실제 38~58초, 목표 45~60초). 즉 문제 수를 3으로 정한 사용자는 고칠 것이
없는데도 경고를 계속 본다.

**확정** — 범위 이탈은 계속 표시하되(#27 완료 조건이다) **결함이 아니라 정보로 다룬다.**
경고 색(`warn`)과 지시형 문구를 쓰지 않고, 총 길이 수치와 목표 구간 막대에 이탈을 표시하는
선에서 끝낸다. 색으로 경고를 띄우는 것은 유튜브 쇼츠 상한을 넘는 쪽(60초 초과)만이다.

시안 값 그대로다. 1.7의 사용 제한만 추가됐다.

### 2.1 색

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `bg/base` | `#0E0F12` | 창 바탕 |
| `bg/panel` | `#121418` | 좌·우 패널 |
| `bg/raised` | `#15171B` | 카드 · 입력 |
| `bg/hover` | `#1C1F24` | 행 호버 |

| `text/2` | `#A2A8B4` | 레이블 — **읽는 11px 문구도 이것을 쓴다 (1.7)** |
| `text/3` | `#6E7480` | 비활성 · 기호 전용 |
| `accent` | `#5B9DFF` | 주요 동작 · 선택 |

선택 상태는 배경 `#22293A` + 안쪽 테두리 `#3E5680`, 선택된 카드는 `#182234` + `accent` 테두리다.

### 2.2 타이포 — Pretendard (번들, 웨이트 3종)

| 토큰 | 크기 / 굵기 | 비고 |
| --- | --- | --- |
| `title` | 20 / 700 / -0.01em | 화면 제목 |
| `heading` | 15 / 700 | 섹션 · 문제 번호 |
| `body` | 14 / 400 / 1.5 | 본문 · 입력 |
| `label` | 12 / 500 · `text/2` | 필드 레이블 |

경로·시간·`confidence`·역할 이름처럼 **기계가 만든 값은 전부 `mono`**다. 시안이 이 규칙을

## 3. 화면 확정 수치

### 3.1 S2 — 메인 편집

```
┌ 헤더 52px ─────────────────────────────────────────────┐
│ 제목 · 경로(mono) · 저장 상태 pill        [저장] [렌더] │
├─────────────┬──────────────────────┬───────────────────┤
│ 장면 296px  │  프리뷰 (남는 폭)     │  속성 340px       │
│             │  9:16 · 정지 프레임   │                   │
│ ─────────── │                      │  ─ 장면 ─         │
│ 총 길이 요약 │                      │  ─ 프로젝트 ─ (1.5)│
└─────────────┴──────────────────────┴───────────────────┘
```

- 창 1440 x 900 기준, 최소 1280 x 720. **최소 폭에서 좌 264 / 우 300으로 줄고 프리뷰가
  우선 유지된다**
- **프리뷰는 높이에 맞추고 폭을 `높이 x 9/16`으로 계산한다.** 시안의 620 x 348.75는 900
  높이일 때의 값이고, 최소 창(720)에서는 세로가 먼저 걸린다 — 폭을 고정하면 프리뷰가 잘린다
- 장면 행: 역할별 색점 8x8(라운드 2px) — `question` `accent` / `answer` `ok` /
  `hook`·`countdown`·`cta` `#8A919E`. 제목 13px, 역할 이름 11px `mono`, 길이 12px `mono`
- **문제 그룹은 머리글 + 들여쓰기 10px으로 묶는다.** 머리글에 `문제 N`과 검증 배지가 함께
  오므로 목록만 보고도 확인이 필요한 문제를 찾을 수 있다
- 총 길이 막대는 0~80초 축에 목표 구간(45~60초 = 56.25%~75%)을 밝은 띠로 깐다

### 3.2 S3 — 문제 편집

- 좌 360px 문제 목록 + 우측 편집 폼. **S2의 3분할이 아니라 2분할이다** — 문제 편집 중에는
  프리뷰가 바뀌지 않으므로 자리를 내주지 않는다
- 목록 행: `Q{n}` + 검증 배지 + (있으면) 재생성 필요 배지 + 난이도, 아래 질문 2줄 말줄임
- 폼 순서: 질문(textarea) → 정답 + 난이도(세그먼트) + 카운트다운(초) → 해설(textarea)
- `flagged` 카드는 폼 맨 위. 사유 문구 + `confidence` 수치 + 120px 막대 + 확인 버튼
- 정답을 성만 적는 식의 표기 불일치가 실제 `flagged` 사례로 시안에 들어 있다 —
  경고 문구는 이렇게 **무엇을 고쳐야 하는지가 보이는** 수준으로 쓴다

### 3.3 S5 — 렌더

네 카드가 같은 폭(520px)으로 온다. 경고 → 진행 → 완료 → 실패.

- **경고 카드의 확인 체크박스를 켜기 전에는 "렌더 시작"이 비활성이다.** 확정 동작이며
  체크박스 문구에 문제 수가 들어간다
- 목록의 각 문제에 "열기"가 있어 S3의 해당 문제로 이동한다
- 진행 카드: 진행률 막대 + `{퍼센트} · {현재 장면}` + 남은 시간. **진행 중에도 다른 화면을
  볼 수 있고 편집만 잠긴다**
- 실패 카드: 사람이 읽는 원인 + 원문 오류(`mono`) + 로그 복사 + 다시 시도.
  실행 명령과 stderr를 run 디렉터리에 남기는 것은 #36의 몫이고 화면은 그 일부를 보여준다

## 4. 상태 표기 체계 — 색이 뜻을 가진다

시안이 세운 구분이고 그대로 확정한다. **네 색이 각각 다른 것을 뜻하며 섞어 쓰지 않는다.**

| 색 | 뜻 | 값이 적용되는가 | 예 |
| --- | --- | --- | --- |
| `danger` 빨강 | **거부** | 아니오 | 지원하지 않는 배경 형식, 저장 실패, 렌더 실패 |
| `warn` 주황 | **경고** | 예 | `flagged`, 낭독보다 짧은 장면 길이, 저장되지 않은 변경 |
| `accent` 파랑 | **해야 할 일** | — | 오디오·자막 재생성 필요 |
| `ok` 초록 | **정상** | — | `verified`, 렌더 완료 |

재생성 필요를 경고와 다른 색으로 둔 것이 핵심이다 — 결함이 아니라 사용자가 해야 할 일이고,
주황으로 그리면 `flagged`와 같은 종류로 읽힌다.

검증 상태 3종은 **색 외에 아이콘 모양과 문구로도 갈린다**(브리프 4.3의 요구다).

| 상태 | 아이콘 | 테두리 | 문구 |
| --- | --- | --- | --- |
| `verified` | `check` | 실선 | `verified` |
| `flagged` | `alert-triangle` | 실선 | `flagged · 확인 필요` |
| `unverified` | `?` | **점선** | `unverified · 확인 필요` |

`unverified`도 확인이 필요한 상태로 묶되(퀴즈 스펙 5.2 — 성공이 아니라 "판단 근거가 없다"),
점선과 문구로 구분한다. `confidence`가 없으므로 수치 자리에 `—`를 쓴다.

## 7. 2차 배치 — S4 잔여 (2026-08-13 수령)

같은 시안 파일에 **"2차 사양" 탭**이 추가된 형태로 왔다. 범위는 발주서 10장 그대로 —
자막 텍스트 편집, 텍스트 오버레이 추가·수정·삭제, 입력값 오류 2종이다. **1차에서 알려준
확정값 여섯 가지는 전부 반영됐고** 시안의 "1차와 달라 고친 값" 표가 반영 지점을 적고 있다.

### 7.1 시안에서 고친 것

#### (1) `hook`과 `cta`에는 낭독이 없다 — 낭독 길이를 주면 안 된다

시안은 장면별 낭독 길이를 `hook 2.1 / question 4.2 / answer 2.6 / cta 2.6`으로 두고
`countdown`만 없음(`—`)으로 처리했다. **`hook`과 `cta`도 없음이다.**

`narrate: true`는 `question`과 `answer`뿐이고(`types/quiz/scene_template.py`), `hook`·`cta`는
고정 길이 장면이다 — 시안이 반영한 2.5초 / 3.0초가 그 고정값이다. 낭독이 없으므로
`audio_duration`이 없고 **길이 미달 경고의 비교 대상 자체가 없다.** 시안대로 구현하면 hook을
2.0초로 줄일 때 존재하지 않는 낭독 2.1초를 근거로 경고가 뜬다.

→ 확정: 낭독 길이는 `question`·`answer`에만 있고 `hook`·`cta`·`countdown`은 `—`이며
길이 경고가 걸리지 않는다.

#### (2) 오버레이 웨이트 400·600은 번들에 없다

시안은 `weight: 400 | 600 | 800`을 제안하며 "번들 Pretendard 3웨이트"라고 적었지만, 번들은
**500 / 700 / 800**이다 (`assets.FONT_FILES` — Medium / Bold / ExtraBold).

앱 CSS가 `font-weight: 400 500`과 `600 700` 범위로 매핑하는 것은 **UI 텍스트용 편의이고
렌더러 계약이 아니다** (`app/src/styles/fonts.css`의 주석이 그 이유를 적어 뒀다). 렌더러는
`assets.font_path(weight)`로 파일을 직접 고르므로 **400·600을 저장하면 `AssetError`로 렌더가
멈춘다.** 화면에서는 정상으로 보이고 렌더에서만 실패하는 종류의 오류다.

→ 확정: `500 | 700 | 800`.

#### (3) 오버레이와 자막 텍스트는 `scenes.json`에 두지 않는다

시안의 스키마는 `scene.overlays: overlay[]`이고 자막 텍스트도 장면 문구를 직접 고치는 모양이다.
**둘 다 `project.json`으로 간다.**

`scenes.json`은 파이프라인이 소유하는 확정 산출물이고 앱이 소유하는 편집 상태는
`project.json`이다 (#28, PRD 14.1). 거기 두면 **재생성(#77)이 장면을 다시 만들 때 사람이 넣은
오버레이와 고친 문구가 사라진다.** 이것은 5장의 장면 길이와 **같은 문제이고, 그래서 같은
자리·같은 키를 쓴다** — `render.scene_overrides`의 항목이 `role` + `question_id`로 장면을
가리키고 `duration` / `text` / `overlays`를 얹는다. 결정문은 PRD 14.1.

#### (4) `countdown`에는 길이 입력이 열려 있으면 안 된다

발주서 10.4에 적었는데 반영되지 않았다 — 시안은 모든 역할에 길이 입력을 보여주고 `countdown`만
경고를 끈다. `duration`이 `seconds`와 같아야 하고 그 값은 콘텐츠 필드이므로 **S3의 카운트다운
초가 소유한다.** 두 화면이 같은 값을 쓰면 어느 쪽이 이기는지 모호해진다.

→ 확정: `countdown` 선택 시 **입력 컨트롤이 없고 읽기 전용 표시만 남는다.** 값은 보이지만
고칠 수 없다.

### 7.2 오버레이 확정 스키마

시안 제안에서 웨이트만 고친 값이다. 나머지 여섯 칸은 그대로 확정한다.

```
overlay {
  id      : str
  text    : str                       # 줄바꿈 허용. 줄 하나 = drawtext 하나
  pos     : top|mid|bottom - left|center|right   (9칸)
  offset  : { x: int, y: int }        # px, 1080x1920 기준. 고른 모서리에서의 거리
  color   : preset | white | muted    # 자유 색 없음
  size    : 28 | 40 | 56              # px
  weight  : 500 | 700 | 800           # 시안 400|600|800에서 고침 (7.1-2)
  timing  : "scene" | { start: float, dur: float }   # 장면 시작 기준 초
}
```

- **`color: preset`은 값을 복사하지 않고 프로젝트 자막 스타일을 참조한다.** 시안의 제안이고
  계약과 맞는다 — 스타일을 바꾸면 오버레이 색이 함께 바뀌고, D1 6.3의 대비 판정이 유지된다.
  값을 복사하면 스타일 교체 후 조합이 △로 내려가도 아무도 모른다
- **폭·줄바꿈 속성이 없다.** 줄바꿈은 입력한 줄 그대로이고 폭은 폰트 크기에서 나온다
  (D1 확정 스펙 7.3)
- `timing`의 기본값은 `"scene"`. 장면 길이를 줄이면 `dur`도 함께 잘리고 경고는 없다 —
  `enable='gte(t,a)*lt(t,b)'`가 자연히 그렇게 되며, 끝 시각은 `video_renderer.align()`이 주는
  장면 끝으로 clamp한다 (경계를 `duration`으로 다시 누적하지 않는다)
- 목록 순서가 겹칠 때 그리는 순서다

### 7.3 자막 텍스트 편집과 낡음 두 종류

시안이 낡음을 **두 상태로 갈랐다.** 파랑 사각 `↻` "자막만 낡음 — 음성은 그대로 쓴다"(자막
재생성 버튼 있음)와 파랑 원형 `♪` "음성까지 낡음"(좌측 3px 강조, S2에서는 읽기 전용이고
재생성은 S3). 색은 같은 `accent` 계열이고 아이콘 모양과 문구로 갈린다 — 4장의 요구를 지킨다.

**이 구분은 `review.stale` 하나로 표현되지 않는다.** #28의 `stale`은 항목 번호 목록 하나이고
"오디오·자막이 낡음"을 뜻한다. 두 상태를 그리려면 목록이 갈려야 한다.

> **여기서 기존 동작 하나가 드러났다.** `app/src/types/quiz.tsx`의 `narration()`이 질문·정답과
> 함께 **해설을 넣는데, 해설은 낭독되지 않는다** — `scene_template`이 해설을 `caption`으로만
> 담고 TTS는 `narrate: true` 장면의 `text`만 읽는다 (`narration.py`). 낡음이 한 종류일 때는
> 해설이 자막을 낡게 하므로 맞는 동작이었지만, **두 종류로 갈린 뒤에는 해설만 고친 경우가
> "음성까지 낡음"으로 잘못 표시된다.** 해설은 "자막만 낡음"으로 내려가야 한다.

- 시안의 자막 텍스트 입력은 장면의 **`text` 한 칸**을 고친다. 상단 질문(`heading`)과
  해설(`caption`)은 이 입력에 들어오지 않는다 — 편집 대상 필드는 #83에서 확정한다
- "자막 재생성" 버튼의 **동작은 #77의 몫이다.** #83은 자리와 상태 표시까지다

### 7.4 확정 수치

- **속성 패널 폭이 340px → 384px로 넓어졌다.** 2차 컨트롤(오버레이 편집 카드)이 그 폭을
  요구한다. 시안에 최소 창 값이 없으므로 함께 확정한다 — **1440에서 384 / 최소 1280에서
  336**이고 3.1의 보간 방식을 그대로 쓴다(계수 0.3). 최소 창에서 좌 264 + 우 336이면 프리뷰에
  680px이 남고, 높이 기준 프리뷰가 요구하는 폭은 376px이므로 성립한다
- **입력값 오류 2종의 차이가 확정됐다** (4장의 색 구분을 컨트롤에서 어떻게 보이는지):

| | `danger` 배경 형식 | `warn` 장면 길이 |
| --- | --- | --- |
| 값 | **적용되지 않는다** — 직전 값으로 남는다 | **적용된다** |
| 프리뷰 | 갱신하지 않는다 | 갱신한다 |
| 총 길이 | 그대로 | 갱신한다 |
| 입력 테두리 | `danger` 색, 값이 되돌아간다 | `warn` 색으로 남는다 |

- 오버레이 삭제는 **확인 단계가 있고 되돌리기가 없다.** 삭제 확인 전에는 목록과 프리뷰가
  그대로다
- 오버레이 저장은 텍스트가 비어 있는 동안 비활성이다

### 7.4-1 구현에서 정한 것 (#83)

시안이 열어 둔 자리이거나 화면만 보고는 알 수 없는 값이다. **여기 적힌 것이 구현 기준이다.**

- **편집 대상 필드는 장면의 `text` 하나다.** 상단 문구(`heading`)는 한 문제의 세 장면이 같은
  값을 공유해서 한 장면에서 고치면 나머지가 갈리고, 해설(`caption`)은 콘텐츠 필드라 S3이 이미
  소유한다 (7.3이 "#83에서 확정한다"고 미뤄 둔 값이다).
- **빈 문구는 적용하지 않고 되돌리기가 따로 있다.** 스키마가 빈 문자열을 거부하므로 올리면
  저장 전체가 실패한다 — 비운 동안은 직전 값이 남고 입력 테두리가 `danger`이며(값이 적용되지
  않았다는 뜻, 4장) 원문으로 돌아가는 길은 되돌리기 버튼이다. 그 버튼은 `text` 키를 지우고,
  같은 항목의 `duration`(#82)은 남는다.
- **9칸은 안전 영역의 모서리에 붙는다** (D1 확정 스펙 1장 — x 80~920 / y 260~1500).
  `offset`은 **고른 모서리에서의 거리**이므로 `bottom`에서 `y`를 키우면 위로 올라간다. 기준
  모서리가 없는 가운데 칸(`mid`·`center`)만 화면 좌표대로 오른쪽·아래가 양수다.
- **색 이름은 프리셋의 색 역할로 옮겨진다** — `preset`→`accent` / `white`→`body` /
  `muted`→`secondary` (`overlay.OVERLAY_COLOR_ROLES`). 렌더러에 색값을 적지 않는 규칙 때문이고
  (D1 확정 스펙 6장), 그래서 `white`도 프리셋에 따라 정확한 흰색이 아니다(`#F2FFFB` 등) — 대비가
  확인된 짝이 그쪽이다.
- **크기별 외곽선은 28→2 / 40→3 / 56→4다.** 크기 대비 6~7%로 D1 확정 스펙 2.1의 대역과 같다 —
  스키마에 두께 칸이 없는 것은 크기 후보가 셋뿐이라 표 하나로 끝나기 때문이다. 줄 간격은
  크기의 1.4배이고(요소 표의 1.33~1.44배 가운데) **그림자는 넣지 않는다**(해설·tail과 같다).
- **줄바꿈은 입력한 그대로다.** 자동 줄바꿈을 넣으면 사람이 넣은 줄과 계산된 줄이 섞인다.
  컬럼(840px)을 넘는 줄은 로그로 경고하고 그대로 그린다 — 넘침은 프리뷰에 보인다 (7.5).
- **오버레이는 자막보다 나중에 그린다.** 필터 순서가 그리는 순서이므로, 사람이 나중에 얹은
  것이 자막 아래로 들어가면 넣은 이유가 사라진다.
- **`{start, dur}` 창은 대표 프레임을 덮지 않을 수 있다.** 프리뷰는 장면 한가운데 프레임이므로
  (#27) 창이 그 시각을 지나지 않으면 오버레이가 프리뷰에 나타나지 않는다 — 값이 반영되지 않은
  것이 아니다. 스모크가 이 순서에 걸려 프레임 비교를 창 지정 **앞으로** 옮겼다.
- **속성 패널 폭 384/336은 두 컨트롤이 요구하는 값이다.** 오버레이 카드의 선택지 줄(색·크기·
  굵기)이 그 폭에서 한 줄에 서고, 레이블 칸은 88px이 아니라 44px이다 — 88px을 떼면 견본이
  붙은 세 칸이 옵션 안에서 줄이 갈린다.

### 7.5 겹침 판정은 넣지 않는다

시안이 물은 것 — 오버레이가 자막 줄과 같은 자리에 놓이면 겹치고, 지금은 막지 않고 순서대로
그린다. **경고를 넣지 않는다.**

근거는 둘이다. 자막 요소의 좌표·폰트 크기는 **렌더러의 표**이므로(D1 확정 스펙 5장, 프리셋에
없다) 앱이 겹침을 판정하려면 그 표를 복제해야 하고, 두 곳이 같은 값을 들면 갈린다. 그리고
겹침은 **프리뷰 정지 프레임에 그대로 보인다** — 이 화면에 프리뷰가 있는 이유가 그것이므로,
보이는 것을 문구로 다시 말할 필요가 없다.
