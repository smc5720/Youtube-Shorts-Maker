# D2 앱 UI 디자인 — 확정 구현 스펙

> **구현 기준은 이 문서다.** 시안과 이 문서가 다르면 이 문서가 이긴다 — 시안이 저장소의
> 확정값을 몇 군데 잘못 알고 있었고 1장·7.1에 그 목록과 근거가 있다.
> 1차 배치(S2 메인 편집 · S3 문제 편집 · S5 렌더 · 상태 시안 · 토큰/컴포넌트)와 2차 배치
> (S4 잔여 — 자막 텍스트 · 텍스트 오버레이 · 입력값 오류)를 모두 수령했고 **더 받을 것이 없다.**
> S1(프로젝트 열기)은 발주하지 않았다 — 토큰·인벤토리로 조립해 이미 동작한다.

## 1. 시안에서 고친 것 (1차 배치)

### 1.1 자막 스타일과 배경의 권장 짝 — 둘이 서로 바뀌어 있다

| 프리셋 | 시안이 적은 배경 | **확정값** |
| --- | --- | --- |
| `impact_yellow` | `deep_navy` | `deep_navy` ○ |
| `neon_mint` | `deep_teal` | **`purple_gradient`** ✕ |
| `orange_card` | `purple` | **`deep_teal_gradient`** ✕ |

민트와 오렌지의 짝이 맞바뀌었다. 확정값은 `assets/caption-styles/presets.json`의 `background`
이고 D1 확정 스펙 6.3에서 ◎로 판정된 짝이다.

**단순한 표기 실수가 아니라 대비가 나쁜 쪽을 기본값으로 만든다.** 시안이 제시한 두 조합은 그
매트릭스에서 △(권장하지 않음)인데, 앱이 스타일을 고를 때 배경을 함께 바꿔 주는 동작이 있으므로
그대로 옮기면 사용자가 스타일을 고르는 것만으로 권장하지 않는 조합에 들어간다. 조합 자체를 막지는
않는다 — 매트릭스에 차단 대상이 없다.

### 1.2 고정 장면 길이 — hook 3.0 / cta 3.5는 옛 값이다

확정값은 `hook` **2.5초** / `cta` **3.0초** / `countdown` 3초(`quiz.countdown_sec` 기본값)다.
D1 확정 스펙 3장에서 시안에 맞춰 짧아진 값이고 PRD 7.5.1·퀴즈 스펙 2장이 같은 값을 쓴다.
시안의 총 길이 표시(48.1초)는 이 두 값 때문에 1.0초 길게 나온 것이다.

### 1.3 산출물 경로와 파일명 — 세 자리가 틀렸다

화면에 그대로 노출되는 값이라 옮겨 적으면 사용자가 없는 경로를 찾게 된다.

| 위치 | 시안 | **확정값** |
| --- | --- | --- |
| 헤더 프로젝트 경로 | `runs/2026-08-11_143022` | `outputs/run-{timestamp}/` |
| 렌더 완료 출력 | `runs/…/out/final.mp4` | `final_short.mp4` (run 디렉터리 **루트**) |
| 렌더 실패 로그 | `audio/answer_02.wav` | `audio/seg-003.mp3` |

세 번째가 특히 중요하다 — 세그먼트 파일명은 **역할 이름이 아니라 장면 배열 인덱스**로 매기고
확장자는 mp3다 (PRD 7.5.2). 앱이 오디오 파일을 가리키는 모든 문구가 이 규칙을 따라야 하며,
낭독이 없는 장면에는 번호가 비어 있다.

### 1.4 "확인함으로 표시"가 `verify.status`를 덮어쓰면 안 된다 — 계약 위반

시안 S3의 `resolveFlag`는 확인 버튼이 `status`를 `verified`로, `confidence`를 `1`로 바꾼다.
**그대로 구현할 수 없다** — 그 두 값은 `quiz_verifier`와 `quiz_review.py`가 소유하고, 사람이
`1`을 써 넣으면 임계값 판정이 **다음 실행에서 조용히 통과한다.** `quiz.json`의 `verify`에는
사람 확인을 기록할 칸도 없다.

**확정 동작** — 사람 확인은 `project.json`의 `review.acknowledged`에 남는다 (PRD 14.1). 화면
쪽은 시안 그대로다: 배지가 `verified`로 바뀌는 것이 아니라 **"확인함" 표시가 추가로 붙고**
S5의 경고 목록에서 빠진다.

### 1.5 자막 스타일과 배경은 장면 속성이 아니다

시안은 우측 패널 머리에 선택된 장면의 역할을 띄우고 그 아래에 자막 스타일·배경·장면 길이·볼륨을
차례로 놓았다. 그런데 **넷 중 셋(자막 스타일·배경·볼륨)은 프로젝트 전역 값**이고 장면별로 다를
수 있는 것은 길이 하나뿐이라, 역할 표시 바로 아래에 오면 "이 장면의 자막 스타일"로 읽힌다.

**확정** — 속성 패널을 두 구획으로 나누고 경계를 시각적으로 드러낸다. 위쪽이 선택된 장면의 값,
아래쪽이 프로젝트 전체의 값이며 아래 구획에 전역임을 알리는 머리글을 둔다.

### 1.6 폰트와 아이콘은 CDN이 아니라 번들에서 온다

시안 `<helmet>`이 Pretendard를 CDN에서 불러오지만 앱은 오프라인으로 동작하고 네트워크 호출이
없다. **구현은 `assets/fonts/`의 번들 폰트를 쓰고** 조회는 `assets.font_path(weight)` 하나다.
아이콘도 Lucide(ISC) 16px / 스트로크 1.5px를 **동봉**하며, 시안의 `!` · `✓` · `×` · `↻` 자리에
`alert-triangle` · `check` · `x` · `refresh-cw`가 들어간다.

### 1.7 `text/3` 토큰의 명도비가 소형 텍스트 기준에 못 미친다

시안이 토큰 페이지에 적은 명도비 세 건은 실측이 오히려 더 높아 문제가 없다(본문 15.90:1 /
보조 7.52:1 / 비활성 3.82:1). **문제는 적지 않은 쪽이다** — `text/3`(`#6E7480`)은 11px `caption`
토큰의 색이기도 한데, 그 크기는 WCAG의 대형 텍스트가 아니라 **소형 텍스트라 AA 기준이 4.5:1**
이고 창 바탕에서 **4.08:1**, 카드에서 **3.82:1**로 미달한다.

**확정** — `text/3`은 비활성 상태와 아이콘·구분 기호에만 쓰고, **읽어야 하는 11px 문구에는
`text/2`(`#A2A8B4`)를 쓴다**(같은 배경에서 7.7:1 / 7.5:1). 교체가 필요한 자리는 장면 목록의 역할
이름, 총 길이 눈금, 프리뷰 하단 캡션, 각 패널의 보조 설명이다. **색표 자체는 바꾸지 않고 쓰이는
자리를 좁힌다.** 계산은 `tests/`가 커밋된 색값에서 다시 한다.

### 1.8 목표 범위 경고는 3문제 구성에서 상시 켜진다

시안의 총 길이 경고는 `total < 45 || total > 60`이고 문구가 지시형("문제를 추가하거나 장면 길이를
늘려야 한다")이다. 그런데 **3문제 구성은 정상 산출인데도 총 길이가 38초대로 나와** 문제 수를 3으로
정한 사용자는 고칠 것이 없는데도 경고를 계속 본다.

**확정** — 범위 이탈은 계속 표시하되 **결함이 아니라 정보로 다룬다.** 경고 색(`warn`)과 지시형
문구를 쓰지 않고 총 길이 수치와 목표 구간 막대에 이탈을 표시하는 선에서 끝낸다. 경고 색은 유튜브
쇼츠 상한을 넘는 쪽(60초 초과)만이다.

## 3. 화면 확정 수치

### 3.1 S2 — 메인 편집

```
┌ 헤더 52px ─────────────────────────────────────────────┐
│ 제목 · 경로(mono) · 저장 상태 pill        [저장] [렌더] │
├─────────────┬──────────────────────┬───────────────────┤
│ 장면 296px  │  프리뷰 (남는 폭)     │  속성 384px       │
│             │  9:16 · 정지 프레임   │                   │
│ ─────────── │                      │  ─ 장면 ─         │
│ 총 길이 요약 │                      │  ─ 프로젝트 ─ (1.5)│
└─────────────┴──────────────────────┴───────────────────┘
```

- 창 1440 x 900 기준, 최소 1280 x 720. **폭은 콘텐츠 크기로 읽는다** — BrowserWindow의 기본
  `width`는 창틀을 포함하므로 `useContentSize: true`가 없으면 이 수치가 나오지 않는다.
- 최소 창에서 좌 264 / 우 336으로 줄고 프리뷰가 우선 유지된다 (보간 계수 0.3).
  **속성 패널은 1차의 340에서 384로 넓어졌다** — 2차 컨트롤(오버레이 편집 카드)이 그 폭을
  요구한다. 최소 창에서 좌 264 + 우 336이면 프리뷰에 680px이 남고 높이 기준 요구폭은 376px이다.
- **프리뷰는 높이에 맞추고 폭을 `높이 x 9/16`으로 계산한다.** 시안의 620 x 348.75는 창 높이 900
  일 때의 값이라 폭을 고정하면 최소 창(720)에서 잘린다.
- 장면 행: 역할별 색점 8x8(라운드 2px) — `question` `accent` / `answer` `ok` /
  `hook`·`countdown`·`cta` `#8A919E`. 제목 13px, 역할 이름 11px `mono`, 길이 12px `mono`.
- **문제 그룹은 머리글 + 들여쓰기 10px으로 묶는다** — 머리글에 `문제 N`과 검증 배지가 함께 오므로
  목록만 보고도 확인이 필요한 문제를 찾을 수 있다.
- 총 길이 막대는 0~80초 축에 목표 구간(45~60초 = 56.25%~75%)을 밝은 띠로 깐다.

### 3.2 S3 — 문제 편집

- 좌 360px 문제 목록 + 우측 편집 폼. **S2의 3분할이 아니라 2분할이다** — 문제 편집 중에는
  프리뷰가 바뀌지 않으므로 자리를 내주지 않는다.
- 목록 행: `Q{n}` + 검증 배지 + (있으면) 재생성 필요 배지 + 난이도, 아래 질문 2줄 말줄임.
- 폼 순서: 질문(textarea) → 정답 + 난이도(세그먼트) + 카운트다운(초) → 해설(textarea).
- `flagged` 카드는 폼 맨 위. 사유 문구 + `confidence` 수치 + 120px 막대 + 확인 버튼.
  경고 문구는 **무엇을 고쳐야 하는지가 보이는** 수준으로 쓴다.

### 3.3 S5 — 렌더

네 카드가 같은 폭(520px)으로 온다. 경고 → 진행 → 완료 → 실패.

- **경고 카드의 확인 체크박스를 켜기 전에는 "렌더 시작"이 비활성이다.** 체크박스 문구에 문제
  수가 들어가고, 목록의 각 문제에 "열기"가 있어 S3의 해당 문제로 이동한다.
- 진행 카드: 진행률 막대 + `{퍼센트} · {현재 장면}` + 남은 시간. **진행 중에도 다른 화면을 볼 수
  있고 편집만 잠긴다.** **취소는 없다** — 취소가 남기는 잘린 mp4를 다루는 것이 #36이다.
- 실패 카드: 사람이 읽는 원인 + 원문 오류(`mono`) + 로그 복사 + 다시 시도.
- **게이트는 하나뿐이다.** 경고 대상은 `flagged`와 `unverified` 둘이고(퀴즈 스펙 5.2) 사람이
  확인한 항목은 빠진다. 재생성 필요·낭독보다 짧은 장면 길이·저장하지 않은 변경은 **같은 카드
  아래에 함께 나열하되 진행을 막지 않는다** — 4장의 색이 그 셋을 갈라 준다.
- **퍼센트와 남은 시간은 화면의 계산이다.** 백엔드가 보내는 것은 진행 프레임 · 총 프레임 · 장면
  인덱스 · 경과 ms이고, "현재 장면"은 그 인덱스로 목록에서 찾은 역할 이름이다.
- **"저장되지 않은 변경"이 이 화면에서 뜻이 하나 더 있다** — 렌더는 앱이 들고 있는 프로젝트로
  돌기 때문에 그 편집이 결과에 들어간다. 4장의 `warn`(값이 적용된다)이 그대로 맞는다.
- **시작 버튼은 카드 더미 아래에 붙어 스크롤에 고정된다** — 낡음 알림이 여럿이면 카드가 창보다
  길어지고, 그때 이 화면에서 하려는 일이 화면 밖으로 나간다.

## 4. 상태 표기 체계 — 색이 뜻을 가진다

**네 색이 각각 다른 것을 뜻하며 섞어 쓰지 않는다.**

| 색 | 뜻 | 값이 적용되는가 | 예 |
| --- | --- | --- | --- |
| `danger` 빨강 | **거부** | 아니오 | 지원하지 않는 배경 형식, 저장 실패, 렌더 실패 |
| `warn` 주황 | **경고** | 예 | `flagged`, 낭독보다 짧은 장면 길이, 저장되지 않은 변경 |
| `accent` 파랑 | **해야 할 일** | — | 오디오·자막 재생성 필요 |
| `ok` 초록 | **정상** | — | `verified`, 렌더 완료 |

재생성 필요를 경고와 다른 색으로 둔 것이 핵심이다 — 결함이 아니라 사용자가 해야 할 일이고,
주황으로 그리면 `flagged`와 같은 종류로 읽힌다.

검증 상태 3종은 **색 외에 아이콘 모양과 문구로도 갈린다.**

| 상태 | 아이콘 | 테두리 | 문구 |
| --- | --- | --- | --- |
| `verified` | `check` | 실선 | `verified` |
| `flagged` | `alert-triangle` | 실선 | `flagged · 확인 필요` |
| `unverified` | `?` | **점선** | `unverified · 확인 필요` |

`unverified`도 확인이 필요한 상태로 묶되(퀴즈 스펙 5.2 — 성공이 아니라 "판단 근거가 없다") 점선과
문구로 구분한다. `confidence`가 없으므로 수치 자리에 `—`를 쓴다.

**입력값 오류 2종의 차이**:

| | `danger` 배경 형식 | `warn` 장면 길이 |
| --- | --- | --- |
| 값 | **적용되지 않는다** — 직전 값으로 남는다 | **적용된다** |
| 프리뷰 | 갱신하지 않는다 | 갱신한다 |
| 총 길이 | 그대로 | 갱신한다 |
| 입력 테두리 | `danger` 색, 값이 되돌아간다 | `warn` 색으로 남는다 |

## 5. 편집 컨트롤

### 5.1 볼륨

슬라이더는 0~100(과 그 위)을 그리고 저장되는 값은 **선형 게인**이다 — 눈금 100 = 게인 1.0.
**구현의 슬라이더는 눈금 200까지 끈다**: 0~100으로는 원본보다 키우는 조작이 화면에서 불가능해지고,
상한을 두지 않는 것이 확정 동작이기 때문이다(최종 오디오는 리미터가 -1 dBFS에서 잡는다). 200은
조작 범위이지 계약의 상한이 아니라 손으로 더 큰 값을 적은 `project.json`도 열리고 값이 깎이지
않는다. 필드는 `audio.voice_volume` / `audio.sfx_volume` (PRD 7.10).

### 5.2 장면 길이

**경고하되 값은 받는다** — 낭독보다 짧아도 적용하고 `warn`으로 알린다. 값이 사는 자리는
`project.json`의 `render.scene_overrides`이고 `scenes.json`은 건드리지 않는다 (PRD 14.1).

- **`hook`·`cta`·`countdown`에는 낭독 길이가 없다.** 시안이 장면별 낭독 길이를 `hook 2.1` /
  `cta 2.6`으로 적었지만 `narrate: true`는 `question`·`answer`뿐이고 나머지는 고정 길이 장면이라
  **길이 미달 경고의 비교 대상 자체가 없다** — 시안대로면 존재하지 않는 낭독을 근거로 경고가 뜬다.
- **`countdown`에는 입력 컨트롤을 두지 않는다.** `duration`이 `seconds`와 같아야 하고 그 값은
  콘텐츠 필드라 S3의 카운트다운 초가 소유한다 — 두 화면이 같은 값을 쓰면 어느 쪽이 이기는지
  모호해진다. **읽기 전용 표시만 남는다.**

### 5.3 배경·자막 스타일

- **목록과 기본 짝은 백엔드가 돌려준다** (PRD 7.9). 앱이 프리셋 이름을 들면 화면에 보이는 목록과
  렌더가 아는 목록이 갈린다.
- **자막 스타일을 고르면 배경이 기본 짝(1.1)으로 함께 바뀌되, 프리셋이 아닌 배경(사용자 파일·색)
  은 건드리지 않는다** — 프리셋 이름으로 표현되지 않는 값이라 갈아 끼우면 사용자가 넣은 것이
  사라진다. 그때는 기본 배경 문구도 띄우지 않는다.
- **배경 프리셋 목록은 배경이 파일일 때도 그린다** — 사용자 파일에서 프리셋으로 돌아오는 길이
  그 목록뿐이라 숨기면 앱에서 넣은 배경을 앱에서 되돌릴 수 없다. 고른 카드만 표시한다.
- **프리셋 목록은 두 칸 격자에 들어가지 않는다** — 88px 레이블 옆에 남는 폭으로는 견본과 이름이
  한 줄에 안 들어가 이름이 잘린다. 레이블을 위로 올리고 목록이 폭을 다 쓴다.

### 5.4 자막 텍스트

- **편집 대상은 장면의 `text` 한 칸이다.** 상단 문구(`heading`)는 한 문제의 세 장면이 같은 값을
  공유해서 한 장면에서 고치면 나머지가 갈리고, 해설(`caption`)은 콘텐츠 필드라 S3이 소유한다.
- **빈 문구는 적용하지 않는다.** 스키마가 빈 문자열을 거부하므로 올리면 저장 전체가 실패한다 —
  비운 동안은 직전 값이 남고 입력 테두리가 `danger`이며(값이 적용되지 않았다는 뜻) 원문으로
  돌아가는 길은 되돌리기 버튼이다. 그 버튼은 `text` 키를 지우고 같은 항목의 `duration`은 남긴다.

### 5.5 텍스트 오버레이

```
overlay {
  id      : str
  text    : str                       # 줄바꿈 허용. 줄 하나 = drawtext 하나
  pos     : top|mid|bottom - left|center|right   (9칸)
  offset  : { x: int, y: int }        # px, 1080x1920 기준. 고른 모서리에서의 거리
  color   : preset | white | muted    # 자유 색 없음
  size    : 28 | 40 | 56              # px
  weight  : 500 | 700 | 800           # 시안 400|600|800에서 고침
  timing  : "scene" | { start: float, dur: float }   # 장면 시작 기준 초
}
```

- **웨이트 400·600은 번들에 없다.** 시안이 "번들 Pretendard 3웨이트"라며 `400|600|800`을 적었지만
  번들은 **500/700/800**이다(`assets.FONT_FILES`). 앱 CSS가 `400 500`·`600 700` 범위로 매핑하는
  것은 UI 텍스트용 편의이고 렌더러 계약이 아니다 — 렌더러는 `assets.font_path(weight)`로 파일을
  직접 고르므로 **400·600을 저장하면 `AssetError`로 렌더가 멈춘다. 화면에서는 정상으로 보이고
  렌더에서만 실패한다.**
- **`color: preset`은 값을 복사하지 않고 프로젝트 자막 스타일을 참조한다.** 스타일을 바꾸면
  오버레이 색이 함께 바뀌어 D1 6.3의 대비 판정이 유지된다 — 값을 복사하면 스타일 교체 후 조합이
  △로 내려가도 아무도 모른다. 이름은 프리셋의 색 역할로 옮겨진다(`preset`→강조 / `white`→본문 /
  `muted`→보조)이므로 **`white`도 프리셋에 따라 정확한 흰색이 아니다** — 대비가 확인된 짝이 그쪽이다.
- **오버레이와 자막 문구는 `scenes.json`에 두지 않는다.** 그 파일은 파이프라인이 소유하는 확정
  산출물이라 재생성이 장면을 다시 만들 때 사람이 넣은 값이 사라진다. 장면 길이와 **같은 문제이고
  그래서 같은 자리·같은 키를 쓴다** — `render.scene_overrides` 항목 하나에 `duration` / `text` /
  `overlays`가 함께 붙는다 (PRD 14.1).
- **폭·줄바꿈 속성이 없다.** 줄바꿈은 입력한 줄 그대로이고 폭은 폰트 크기에서 나온다 — 자동
  줄바꿈을 넣으면 사람이 넣은 줄과 계산된 줄이 섞인다. 컬럼(840px)을 넘는 줄은 로그로 경고하고
  그대로 그린다(넘침은 프리뷰에 보인다).
- **9칸은 안전 영역의 모서리에 붙고 `offset`은 고른 모서리에서의 거리다** — `bottom`에서 `y`를
  키우면 위로 올라간다. 기준 모서리가 없는 가운데 칸만 화면 좌표대로 오른쪽·아래가 양수다.
- **크기별 외곽선은 28→2 / 40→3 / 56→4**(크기 대비 6~7%로 D1 2.1의 대역과 같다). 줄 간격은
  크기의 1.4배이고 **그림자는 넣지 않는다**. 스키마에 두께 칸이 없는 것은 크기 후보가 셋뿐이라
  표 하나로 끝나기 때문이다.
- **오버레이는 자막보다 나중에 그린다** — 필터 순서가 그리는 순서이므로 사람이 나중에 얹은 것이
  자막 아래로 들어가면 넣은 이유가 사라진다. 목록 순서가 겹칠 때 그리는 순서다.
- `timing` 기본값은 `"scene"`. 장면 길이를 줄이면 `dur`도 함께 잘리고 경고는 없다 — 끝 시각은
  `video_renderer.align()`이 주는 장면 끝으로 clamp한다. **`{start, dur}` 창은 프리뷰에 안 보일
  수 있다** — 프리뷰는 장면 한가운데 프레임이라 창이 그 시각을 덮지 않으면 프레임이 그대로다
  (값이 반영되지 않은 것이 아니다).
- 삭제는 **확인 단계가 있고 되돌리기가 없다.** 저장은 텍스트가 비어 있는 동안 비활성이다.
- **속성 패널 폭 384/336은 이 컨트롤이 요구하는 값이다** — 선택지 줄(색·크기·굵기)이 그 폭에서
  한 줄에 서고, 레이블 칸은 88px이 아니라 44px이다.

### 5.6 겹침 판정은 넣지 않는다

오버레이가 자막 줄과 같은 자리에 놓이면 겹치지만 경고하지 않는다. 자막 요소의 좌표·폰트 크기는
**렌더러의 표**이므로(D1 확정 스펙 5장) 앱이 판정하려면 그 표를 복제해야 하고 두 곳이 갈린다.
그리고 **겹침은 프리뷰 정지 프레임에 그대로 보인다** — 이 화면에 프리뷰가 있는 이유가 그것이므로
보이는 것을 문구로 다시 말할 필요가 없다.

## 6. 낡음 표시 두 종류

파랑 사각 `↻` **"자막만 낡음"**(자막 재생성 버튼 있음)과 파랑 원형 `♪` **"음성까지 낡음"**(좌측
3px 강조, S2에서는 읽기 전용이고 재생성은 S3)으로 갈린다. 색은 둘 다 `accent`이고 아이콘 모양과
문구로 구분한다 (4장의 요구다).

- **재생성은 경로가 하나다** — 두 카드의 버튼과 S5의 "재생성 실행"이 같은 실행을 부르고, 두 낡음이
  갈리는 것은 TTS 재합성이 일어나는지뿐이며 그 판단은 `audio/segments.json`이 한다.
  **"자막만 낡음"이어도 `voice.mp3`는 다시 만든다** — 해설이 길어지면 자막 읽기 하한이 그 장면의
  길이를 늘려 뒤 장면 시작 시각이 전부 밀린다 (PRD 14.1).
- **버튼은 셸이 만들어 타입 폼에 내려보낸다** (`EditorProps.regenerate`). 문구는 낡음 종류로
  갈리지만 부르는 것은 하나이고, 그 판단도 실행도 타입의 지식이 아니다.
- **진행 표시는 화면이 아니라 알림 자리에 선다** (3.3의 렌더와 같은 규칙). 단계 이름과 세그먼트
  `n/m`이 오고 **퍼센트가 없다** — 단계마다 걸리는 시간이 크게 다르다.
- 기록 자리는 `project.json`의 `review`이고 칸이 셋이다 (PRD 7.10).

> **장면 순서 변경은 문제 순서 변경으로 이미 들어와 있다.** `app/src/types/index.ts`의 `items`가
> "순서가 곧 장면 순서다"이고 `hook`·`cta`는 위치가 고정이므로, S2 속성 패널에 순서 컨트롤을
> 다시 두지 않는다.
