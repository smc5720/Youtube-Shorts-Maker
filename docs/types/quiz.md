# 쇼츠 타입: 퀴즈 (Quiz)

> 이 문서는 [PRD](../PRD.md)의 하위 스펙이다. 쇼츠 "타입"의 첫 구현 대상인 **퀴즈**를 정의한다.

## 0. 결정 요약

| 항목 | 결정 |
|------|------|
| 서브 장르 | 상식/지식 퀴즈 (`general_knowledge`) |
| 문제 수 | 3~5개 연속형 (기본 4개) |
| 정답 형식 | 주관식 (정답 공개형, 선택지 없음) |
| 콘텐츠 확보 | LLM 자동 생성 |
| TTS 범위 | 질문 + 정답 낭독 (해설은 자막만) |
| 사운드 | 카운트다운 비프 / 정답 효과음 기본 탑재 (자체 생성, 7장) |
| 사실 검증 | 2차 LLM 검증 단계 기본 포함 |

## 1. 타입 플러그인 개념

앞으로 쇼츠 타입이 여러 개(퀴즈, 스토리, 랭킹, 정보 요약 등) 추가된다. 타입을 1급 개념으로
도입하고, 타입별로 두 가지를 플러그인처럼 교체한다.

- **콘텐츠 생성기**: 입력 → 타입 전용 콘텐츠 산출물 (퀴즈는 `quiz.json`)
- **장면 템플릿**: 콘텐츠 → `scenes.json` (타입별 장면 레이아웃/타임라인 규칙)

렌더러·TTS·자막은 공통 파이프라인을 공유하되, 타입 전용 렌더 요소(카운트다운 오버레이, 정답
강조)를 `role`로 구분해 추가한다. 구현은 `shorts_types.py`의 레지스트리이고 퀴즈의 선언은
`types/quiz/__init__.py`의 `SHORTS_TYPE`이다 — 레지스트리는 타입 이름과 그 위치만 안다.

### 1.1 경계 규칙: 공통 파이프라인은 `scenes.json`만 본다

**TTS·자막·렌더러·메타데이터 생성기는 `scenes.json`만 읽고 `quiz.json`을 열지 않는다.**

| 모듈 | 읽는 것 | 읽지 않는 것 |
| --- | --- | --- |
| `quiz_generator` / `quiz_verifier` | 입력 주제 | — |
| 장면 템플릿 (`scene_template.py`) | `quiz.json` | — |
| `tts` / `captions` / `video_renderer` / `metadata_generator` | `scenes.json` | **`quiz.json`** |

- 렌더에 필요한 타입 전용 정보는 장면 템플릿이 `scenes.json` 필드로 옮겨 담는다. 예:
  `countdown_sec` → `countdown` 장면의 `seconds`·`duration`, `explanation` → `answer` 장면의
  `caption`.
- 타입 전용 렌더 요소도 `role` 값으로만 구분한다. 렌더러는 `role: "countdown"`을 보고
  오버레이를 그리지만 그 장면이 퀴즈에서 나왔다는 사실은 모른다 — 다른 타입이 같은 `role`을
  쓰면 같은 오버레이를 그대로 얻는다.
- 세그먼트 오디오 파일명도 장면 인덱스로만 매긴다 (`audio/seg-003.mp3`).

**이 표는 `tests/test_type_boundary.py`가 강제한다.** `types/` 밖의 모듈이 타입 패키지를
import하거나 `load_quiz`를 쓰거나 타입 전용 파일명을 문자열로 들고 있으면 테스트가 깨진다.
PRD 쪽 서술은 [7.4.1](../PRD.md#741-scenesjson-단일-계약).

## 2. 포맷 / 타임라인

문제당 약 10초, 기본 4문제 기준 약 47초.

> **아래 초 단위 값은 목표치이며 최종 길이가 아니다.** 질문·정답 장면의 실제 `duration`은
> 합성된 오디오의 실측 길이 + 앞뒤 패딩으로 확정된다 ([PRD 7.5.1](../PRD.md)). "질문 3초"를
> 고정값으로 구현하면 자막·정답 강조·효과음이 음성과 어긋난다.

```text
[0~2.5초]   후킹        강한 첫 문장 (예: "이 상식 4개, 다 맞히면 상위 1%")
── 문제 블록 (문제 수만큼 반복) ──
  [질문 ~4초]   질문 텍스트 크게 표시 + TTS 질문 낭독               ← 실측 확정
  [카운트 3초]  3 → 2 → 1 타이머 오버레이 + 비프음                  ← 고정
  [정답 ~3초]   정답 강조 + 한 줄 해설(자막) + 효과음 + TTS 정답 낭독 ← 실측 확정
── 반복 끝 ──
[마지막 3초]  CTA        "몇 개 맞혔나요? 댓글 + 구독"
```

| 장면 | 길이 결정 | 근거 |
| --- | --- | --- |
| `hook` | 고정 2.5초 | 현재 TTS 범위가 질문·정답뿐이라 낭독이 없다 |
| `question` | 실측 오디오 + 패딩 | 질문 문장 길이가 문제마다 다르다 |
| `countdown` | 고정 `countdown_sec` (기본 3초) | 낭독이 없고 숫자 전환이 정수 초에 맞아야 한다 |
| `answer` | 실측 + **해설 읽기 시간 하한** | 정답 낭독 길이 편차가 크고, 해설은 낭독이 없어 별도 하한이 필요하다 |
| `cta` | 고정 3.0초 | 낭독이 없다 |

- 길이 가이드: 3문제 ≈ 36초 / 4문제 ≈ 47초 / 5문제 ≈ 57초. 확정 합계가 PRD 6.3의 45~60초를
  벗어나면 경고만 남기고 렌더는 진행한다.
- **난이도 오름차순 배치**(easy → hard)로 이탈을 방지한다. 후킹의 "상위 1%"는 마지막 고난도
  문제로 정당화한다.
- `hook`·`cta`에 낭독을 추가하기로 하면 두 장면은 `narrate: true`가 되고 자동으로 실측 규칙을
  따른다 — 고정 길이 목록을 코드에 하드코딩하지 않는다.

## 3. 데이터 스키마

콘텐츠(`quiz.json`)와 렌더 계획(`scenes.json`)을 분리한다. `quiz.json`이 사람이 검수·수정하는
원본이다. **필드명은 `src/shorts_maker/schemas/`가 확정하고 이 문서는 설명하는 쪽이다.**

### 3.1 `quiz.json`

```json
{
  "schema_version": 1,
  "type": "quiz",
  "category": "general_knowledge",
  "language": "ko",
  "hook": "이 상식 4개, 다 맞히면 상위 1%",
  "cta": "몇 개 맞혔나요? 댓글로 알려주세요!",
  "questions": [
    {
      "id": 1,
      "question": "세계에서 가장 긴 강은?",
      "answer": "나일강",
      "explanation": "약 6,650km로 세계에서 가장 긴 강입니다.",
      "difficulty": "easy",
      "countdown_sec": 3,
      "verify": { "status": "verified", "confidence": 0.95, "source": "근거 요약" }
    }
  ]
}
```

- `difficulty`: `easy` | `medium` | `hard`. 장면 배치가 이 순서를 따른다.
- `verify.status`: `verified` | `unverified` | `flagged`.
- **`verify`는 `quiz_generator`가 만든 직후에는 없다** — `quiz_verifier`가 채우므로 검증기는
  이 필드를 필수로 요구하지 않는다. `source`는 근거를 대지 못하는 검증도 있으므로 선택이다.

### 3.2 `scenes.json` (파생)

문제 1개 → 서브 장면 3개(질문/카운트다운/정답). 후킹·CTA는 별도 장면. 장면 템플릿이 만드는
것은 **초안**이고, `narrate: true` 장면의 `duration`은 TTS 단계가 실측값으로 덮어쓴다.
아래는 확정 상태다.

```json
{
  "schema_version": 1,
  "type": "quiz",
  "scenes": [
    { "role": "hook", "kicker": "상식 퀴즈",
      "text": "이 상식 4개, 다 맞히면 상위 1%", "duration": 2.5 },
    { "role": "question", "question_id": 1, "heading": "세계에서 가장 긴 강은?",
      "text": "세계에서 가장 긴 강은?",
      "narrate": true, "target_duration": 3.0, "duration": 2.94,
      "audio": "audio/seg-001.mp3", "audio_duration": 2.14, "narration_offset": 2.8 },
    { "role": "countdown", "question_id": 1, "heading": "세계에서 가장 긴 강은?",
      "seconds": 3, "duration": 3.0, "sfx": "beep" },
    { "role": "answer", "question_id": 1, "heading": "세계에서 가장 긴 강은?",
      "text": "나일강", "caption": "약 6,650km로 세계 최장",
      "narrate": true, "target_duration": 3.0, "duration": 2.733,
      "audio": "audio/seg-003.mp3", "audio_duration": 0.92, "narration_offset": 8.74,
      "sfx": "correct" },
    { "role": "cta", "text": "몇 개 맞혔나요? 댓글로 알려주세요!", "duration": 3.0 }
  ]
}
```

- `target_duration`은 템플릿이 넣은 목표치이고 확정값과 크게 벌어졌는지 검증할 때만 쓴다.
- `audio` / `audio_duration` / `narration_offset`은 TTS 단계가 채우고 장면 템플릿은 비워 둔다.
  `audio` 인덱스는 `scenes` 배열 위치(0-based)라 낭독이 아닌 번호는 비어 있다.
- **위 예시의 정답 장면 2.733초는 낭독 기준값 1.72초가 아니라 해설 읽기 하한에서 나왔다**
  (`caption_onset(0.9) + 16자/12cps + tail(0.5)`, PRD 7.5.1).
- `heading`은 블록 내내 상단에 유지되는 문구다. 장면 템플릿이 question·countdown·answer 세
  장면에 같은 값을 넣는다 — 질문 장면에서는 `text`와 중복이지만 정답 장면에서는 `text`가
  정답이고 `heading`이 질문이라 두 필드가 갈라져야 하고, 렌더러 규칙을 **"`heading`이 있으면
  상단에 그린다"** 하나로 두는 편이 싸다.
- `kicker`는 본문 위 작은 라벨이고 hook 장면에만 있다. 장면 템플릿이 `category`를 한국어
  라벨로 옮기며(`general_knowledge` → `상식 퀴즈`) **매핑은 타입 패키지가 소유한다.** 매핑에
  없는 카테고리를 만나면 장면 템플릿이 오류로 멈춘다 — 영어 이름을 내거나 라벨을 비우면 렌더
  결과를 보고서야 알아채게 되고 고칠 것은 라벨 한 줄이다.
- 두 이름을 `question_text`/`category_label`로 하지 않은 것은 `explanation`을 `caption`으로
  옮긴 것과 같은 이유다 — **통과 필드는 타입 중립 어휘를 쓴다** (1.1).
- **위 예시는 이 문서가 아니라 코드가 검증한다** — `tests/test_schemas.py`가 이 JSON 블록을
  읽어 `validate_scenes_final()`에 넣으므로 스키마에 없는 필드를 예시에만 적으면 깨진다.

> 검증은 두 단계다 — `validate_scenes()`는 초안과 확정 상태를 모두 받고,
> `validate_scenes_final()`은 모든 장면의 `duration`과 낭독 장면의 오디오 필드를 요구한다.
> 스키마가 추가로 요구하는 것: `narrate: true`에는 `text`와 `target_duration`,
> `role: "countdown"`에는 `seconds`. **선언하지 않은 필드는 오류다** — `narate`처럼 오타 난
> 플래그가 "낭독 아님"으로 조용히 통과하면 음성 없는 영상이 나온다.

### 3.3 `project.json` 연동

장면 배열을 복사하지 않고 `scenes.json` 경로만 참조한다. 필드 목록은
[PRD 7.10](../PRD.md#710-프로젝트-파일).

## 4. 파이프라인

퀴즈 타입일 때 PRD의 `summarizer → script_generator` 단계를 아래로 대체한다.

```text
입력(주제)
  → quiz_generator   : LLM으로 Q&A 세트 생성 → quiz.json 초안 (안에서 검증기를 부른다)
  → scene_planner    : 퀴즈 템플릿으로 scenes.json 초안 생성
  → tts              : narrate 장면별 세그먼트 → 실측 길이로 duration 확정 → voice.mp3
  → captions         : 확정 duration·오프셋 기준 SRT
  → video_renderer   : FFmpeg 합성 + 카운트다운·정답 강조 오버레이 + 효과음 믹싱
  → metadata_generator
```

`tts` 이후 단계는 모두 확정된 `scenes.json`을 입력으로 받는다 — 초안의 목표치를 기준으로
계산하는 단계가 있으면 안 된다.

퀴즈 타입은 `script.txt`·`summary.json`을 생성하지 않는다 (PRD 6.2). **`source.json`은 타입이
아니라 입력 경로가 결정한다** — `--text-file`·`--url` 실행에서는 퀴즈 타입에서도 남고, 그때
콘텐츠 생성기가 받는 것은 제목뿐이며 본문은 그 파일에만 있다 (PRD 14.1).

`quiz_generator`와 `quiz_verifier`는 파이프라인 단계가 아니라 **한 단계 안의 두 모듈**이다.
`SHORTS_TYPE.generator`가 가리키는 것은 `generate()` 하나이고 그 안에서 검증기를 부른다.

### 4.1 `quiz_generator`가 정하는 것과 묻지 않는 것

**LLM을 1회 부른다** — 문제별로 나눠 부르면 CLI 기동 오버헤드(호출당 약 6.5초)가 문제 수만큼
곱해진다. 모델에게 묻는 것은 `hook` / `cta` / 각 문제의 `question`·`answer`·`explanation`·
`difficulty`뿐이고 나머지는 코드가 채운다.

| 필드 | 채우는 주체 |
| --- | --- |
| `schema_version` / `type` | 스키마 |
| `category` / `language` | 코드 고정 — `general_knowledge` / `ko` |
| `id` | 난이도 오름차순 정렬 **뒤에** 1부터 다시 매긴다 |
| `countdown_sec` | `quiz.countdown_sec` (모든 문제에 균일) |
| `verify` | `quiz_verifier`. 초안에는 없다 |

- **난이도 오름차순은 프롬프트와 정렬 양쪽에서 보장한다** — 스키마는 값 사이의 순서를 강제하지
  않으므로 프롬프트만으로는 어긋난 배치가 검증을 통과한다.
- `--json-schema`로 넘기는 JSON Schema는 `schemas/quiz.py`의 `content_json_schema()`가
  `quiz.json` 스키마에서 **파생**한다. 프롬프트에 필드 이름을 다시 적으면 계약이 두 곳에 생긴다.

설정이 생성 결과를 좌우한다.

| 키 | 기본값 | 위반 시 |
| --- | --- | --- |
| `quiz.question_count` | 4 | **3~5 밖이면 run 디렉터리를 만들기 전에 오류.** 범위를 아는 것은 퀴즈 타입이므로 설정 로더가 아니라 `ShortsType.config_check`가 확인한다 |
| `quiz.hook_max_len` | 36 | JSON Schema의 `maxLength`로 먼저 걸러지고, 그래도 넘으면 **재생성하지 않고 오류로 멈춘다** — 다시 불러도 같은 결과가 나온다 |
| `quiz.question_max_len` | 45 | 위와 같다 |
| `quiz.answer_max_len` | 20 | 위와 같다 |
| `quiz.cta_max_len` | 24 | 위와 같다 |
| `quiz.explanation_max_len` | 60 | 위와 같다 |

- **글자 수 상한 다섯 개는 레이아웃에서 나온 값이다** ([D1 확정 스펙](../design/d1-video-design-spec.md)
  5장). 각 값은 그 요소의 **가장 작은 폰트 티어가 담는 최대 글자 수**이고 넘으면 텍스트가 안전
  영역을 벗어난다. 상한을 올리려면 렌더 티어를 함께 봐야 한다.
- **렌더 단계에서 자르지 않는다** — 잘린 문장은 화면에서 말이 안 되고 사람이 검수할 원문도
  사라진다. 생성 단계에서 막는다.
- 키 이름은 규약이다 — 생성기가 필드 이름에서 `quiz.<필드>_max_len`을 만들어 스키마와 프롬프트
  양쪽에 싣는다 (`quiz_generator.CAPPED_FIELDS`). CTA의 `punch`·`tail`은 config 고정 문구라
  생성 대상이 아니다.

## 5. 사실 검증 (필수)

주관식 + 상식 + LLM 자동 생성은 **오답 리스크**가 가장 크다. 틀린 정답은 댓글에서 즉시
지적되어 채널 신뢰도를 훼손한다.

### 5.1 검증 방식

검증은 **`generate()` 안의 한 단계**다 — 교체 가능한 축은 생성기와 장면 템플릿 둘뿐이고,
검증은 퀴즈 타입이 자기 산출물에 대해 하는 일이므로 세 번째 축이 되지 않는다.

프로브가 두 개이고 **둘 다 원래 정답을 프롬프트에 넣지 않는다.**

| 프로브 | 묻는 것 | 잡는 것 |
| --- | --- | --- |
| 블라인드 재답변 (`llm.verifier.runs`회) | 질문만 주고 독립 답변 | 정답이 틀린 문제 |
| 모호성 프로브 (1회) | "이 질문은 답이 하나로 정해지는가" | 정답은 맞지만 질문이 모호한 문제 |

**모호성 프로브가 따로 있는 이유** — *정답이 틀린 게 아니라 질문 표현이 모호한* 유형은
블라인드 재답변으로 원리상 잡히지 않는다(재답변 모델도 같은 근거로 같은 답을 낸다). 이 프로브는
정답 일치 여부와 **독립적으로** `flagged`를 만든다.

**호출은 문제 수와 무관하게 `runs + 1`회다.** 문제를 한 호출에 묶어도 새는 것은 질문뿐이지
정답이 아니고 — 블라인드성은 "원래 정답이 프롬프트에 없다"로 정의된다 — 한 영상의 문제들은
애초에 같은 주제로 한 번에 생성된 것이라 주제 인접성은 이미 공유돼 있다.

정답 대조는 **정규화 후 포함 관계**로 한다. 표기 차이(`"나일강"`/`"나일 강"`, `"H2O"`/`"H₂O"`)를
오답으로 세면 검증이 사실 검사가 아니라 표기 검사가 된다. 두 값이 모두 수일 때만 정확 일치를
요구한다 — `"234"`가 `"1234"`에 포함된다고 같은 답으로 세면 연도·개수 문제가 무력해진다.

#### `confidence` 산출

```text
confidence = 일치율 × 평균 자기 확신도
  일치율   = 원래 정답과 일치한 재답변 수 ÷ 성공한 재답변 호출 수
  확신도   = 재답변 모델이 자기 답에 대해 보고한 값 (0~1)의 평균
```

일치율만 쓰면 `runs: 2`에서 값이 `{0, 0.5, 1}` 세 개뿐이라 임계값 0.8이 "2회 전부 일치"와
완전히 같은 뜻이 되고, 임계값을 조정할 수 있다는 전제가 허구가 된다. `runs`를 올려 해상도를
얻는 길은 호출이 선형으로 늘어나 막혀 있다(검증은 이미 문제당 비용의 59%다). 확신도를 곱하면
`runs: 2`에서도 연속값이 나오고, 확신도가 1을 넘지 못하므로 **일치율 0.5인 문제의 상한이
0.5**다 — 임계값을 0.5 위에 두는 한 불일치가 통과하지 못한다.

#### 상태 판정

| 조건 | `status` |
| --- | --- |
| 모호성 프로브가 "답이 갈린다"고 답함 | `flagged` |
| 재답변·프로브 호출이 실패해 판단 근거가 없음 | `unverified` |
| 재답변이 원래 정답과 갈림 | `flagged` |
| 위 어디에도 걸리지 않음 | `verified` |

- `verified`는 **"정답이 맞다"가 아니라 "검증 단계가 결함을 찾지 못했다"**는 뜻이다.
- **임계값은 여기서 적용하지 않는다** (5.2). 재답변 불일치와 질문 모호는 임계값과 무관한
  실검출이라 바로 `flagged`가 되고, 임계값은 남은 `verified`를 확신도 축에서 자른다.
- 검증이 전부 실패해도 **예외를 던지지 않는다** — 여기서 멈추면 이미 지불한 생성 비용이 버려지고
  사람이 검수할 대상 자체가 사라진다.
- `verify.source`는 판정 사유를 앞에 두고 근거를 잇는다 (`"재답변 불일치 — 2회 중 0회 일치…"`).
  근거를 대지 못한 검증에는 키를 넣지 않고 빈 문자열을 남기지 않는다 (3.1).
- `llm.verifier.runs`는 1 이상이어야 하고 위반은 run 디렉터리를 만들기 전에 걸린다 — 재답변이
  한 번도 없으면 검증 단계가 이름만 남는다.

검출률 실측은 [`docs/spikes/10-verifier-detection.md`](../spikes/10-verifier-detection.md).

### 5.2 임계값 판정과 경고

검증기가 산출한 `confidence`를 정책과 대조해 `verify.status`를 확정한다. 구현은
`quiz_review.py`이고 파이프라인은 이것을 **콘텐츠 산출물을 쓰기 전에** 부른다 — 판정이
`quiz.json`에 남아야 앱과 이후 단계가 같은 상태를 본다.

| 확정 전 | 조건 | 확정 후 |
| --- | --- | --- |
| `verified` | `confidence` ≥ `llm.verifier.confidence_threshold` | `verified` |
| `verified` | `confidence` < 임계값 | `flagged` (사유: 임계값 미달) |
| `unverified` | — | `flagged` (검증기가 적은 사유를 유지) |
| `flagged` | — | `flagged` (사유를 덮어쓰지 않는다) |

- **임계값 키는 `llm.verifier.confidence_threshold` 하나다** (기본 0.8). 같은 뜻의 키를 `quiz`
  아래에 새로 만들지 않는다. 임계값과 정확히 같은 값은 통과다 (`<`로 자른다).
- **임계값 미달은 실검출보다 뒤에 온다** — 이미 잡힌 문제에 "임계값 미달"을 덧쓰면 더 구체적인
  사유를 잃는다.
- `unverified`도 `flagged`가 된다. 성공이 아니라 "판단 근거가 없다"이고, 근거 없이 통과시키면
  검증 단계를 둔 뜻이 없다. 원래 사유는 `source`에 남아 계속 구분된다.
- **두 번 불러도 결과가 같다** — 사유를 먼저 `source`에 쓰고 경고 문구를 거기서 만든다.

**기본 동작은 경고 후 진행이고 종료 코드는 0이다** — MVP의 검수 주체는 사람이고 사람은 산출물이
있어야 검수한다. 중단이 필요한 쪽은 `--fail-on-flagged`로 전용 종료 코드를 얻는다. 경고는 문제
`id`·질문·`confidence`·임계값·사유를 담아 콘솔과 `run.log`에 남는다(`--verbose`와 무관).
**앱에서는 렌더 화면의 경고 목록이 그 자리이고 확인 체크박스가 게이트다** — `unverified`도 함께
오고 사람이 확인한 항목(`review.acknowledged`)은 빠진다. **판정은 앱이 하고 백엔드는 막지
않는다** (막으면 CLI의 이 규칙과 갈린다).

파이프라인은 판정 기준을 모른다 — 타입이 만든 `ContentIssue`(어느 부분 / 무엇 / 왜) 세 칸을
읽어 경고로 옮길 뿐이며 `confidence`도 임계값도 퀴즈 타입 안에만 있다.

#### 임계값 0.8의 근거

의미 있는 범위가 `(0.5, 0.98)`이고 0.8이 그 가운데다 — 아래로는 `confidence = 일치율 × 확신도`의
성질상 재답변이 갈린 문제의 상한이 0.5라 그 이하로 두면 불일치를 통과시키고, 위로는 관측된 정상
문제의 최솟값이 0.98이라 그 위로 올리면 정상 문제를 잃기 시작한다.

**임계값은 모호성 프로브의 대체재가 아니다.** 측정에서 검증기가 놓친 모호 문제의 `confidence`
(0.865~0.99)가 정상 문제 대역(0.98~1.0)과 겹쳤다 — 누락을 임계값으로 되찾으려면 0.99를 넘겨야
하고 그러면 정상 문제도 함께 잘린다.

## 6. 렌더링 요소 (퀴즈 전용)

- **카운트다운 오버레이**: 큰 숫자 + 하단 진행 바. `seconds`부터 1까지 초당 하나씩 갈아 끼운다.
  원형 타이머는 채택하지 않았고, **진행 바는 1초 단위 계단이다** — `drawbox`의 폭을 시간
  표현식으로 제어할 수 없는 것이 실측됐다 ([D1 확정 스펙 2.3](../design/d1-video-design-spec.md)).
- **정답 강조**: 정답 텍스트 등장 애니메이션 (스케일 확대 + 색 전환). **`answer` 장면의 질문은
  감쇠색으로 남긴다** — 숨기면 정답이 아직 없는 0.15초 동안 화면이 거의 비어 렌더 사고처럼
  보이고 정답이 무엇에 대한 답인지도 사라진다.
- **효과음**: 카운트다운 비프(숫자가 갈리는 프레임마다), 정답 공개(등장 순간 한 번).
  `assets/sfx/`에 번들하며 **FFmpeg 사인 합성으로 자체 생성한다** — 저장소와 앱에 동봉되므로
  제3자 조건이 없는 쪽을 택했다 (생성 도구 `tools/generate_sfx.py`).

수치는 [D1 확정 스펙 5장](../design/d1-video-design-spec.md), 믹스 규칙은 PRD 7.7.

## 7. 에셋

```text
assets/
  backgrounds/      # 세로형 배경 (공통)
  sfx/
    beep.mp3        # 카운트다운
    correct.mp3     # 정답 공개
    CREDITS.md      # 출처·라이선스·측정값
  music/            # 라이선스 확인된 파일만
```

**파일 stem이 `scenes.json`의 `sfx` 값이다.** 값을 정하는 곳은 장면 템플릿
(`COUNTDOWN_SFX`/`ANSWER_SFX`)이고 이름에서 경로를 찾는 것은 `assets.sfx_path()` 하나다.
규격은 mp3 / 48kHz / 스테레오, `beep` 1.0초 이하 · `correct` 1.5초 이하, peak는 둘 다
-12 dBFS 이하에 편차 3dB 이내.

**낭독 대비 최종 믹스 레벨은 기본 게인 1.0 그대로다** — 두 파일이 낭독보다 9.5dB 아래로
정규화돼 있다. 조정은 `audio.sfx_volume`이고 `0`이면 효과음이 없는 결과가 나온다.

긴장 사운드(`tension.mp3`)는 **번들하지 않는다** — 장면 템플릿이 이 이름을 내지 않으므로 쓰이지
않는 바이너리가 된다.

## 8. 편집 앱 연동

- 장면 목록에 후킹 / 문제(질문·카운트다운·정답) / CTA를 구분 표시한다.
- 문제별로 질문·정답·해설·난이도·카운트다운 길이를 수정하고, 순서 변경·추가·삭제를 지원한다.
- 검증이 통과하지 못한 문제는 배지로 표시한다.
- 나머지 편집 기능은 PRD 6.5 공통 기능을 따른다.

위 목록을 그대로 읽으면 틀리는 지점 셋:

- **배지 색은 빨강이 아니다.** 빨강(`danger`)은 **거부**(값이 적용되지 않음)이고 `flagged`는
  주황(`warn`)이다 — 렌더는 그대로 진행되므로 거부 색을 쓰면 사용자가 렌더가 막힌 것으로 읽는다.
  `unverified`도 같은 주황이되 점선 테두리와 `?` 기호로 갈린다.
- **사람이 확인해도 `verify`는 바뀌지 않는다** — `status`와 `confidence`는 검증기와
  `quiz_review.py`가 소유하는 판정 입력이라, 사람 판단이 그 칸을 덮으면 다음 실행의 임계값
  판정이 조용히 통과한다. 확인 기록은 `project.json`의 `review.acknowledged`이고
  **`--fail-on-flagged` 자동화 경로는 이 기록을 보지 않는다.**
- **앱에서 고친 것이 곧바로 영상에 반영되지 않는다.** 순서·개수·낭독 문구를 고쳐도
  `scenes.json`·오디오·자막은 그대로이고 앱은 낡았다고 표시만 한다. 다시 만드는 것은
  **재생성**이다 — `scene_template` → 세그먼트(재사용/합성) → 타임라인 → `voice.mp3` →
  `captions.srt` → `project.json` 순서로 다시 만들고 낡음 표시를 지운다. **이 경로는 모델을
  부르지 않으므로** 사람이 고친 `quiz.json`이 덮이지 않고, 그 대가로 `metadata.json`은 옛
  제목·태그로 남는다. **`countdown_sec`을 고친 것이 장면에 도달하는 자리도 여기다** — 재생성
  전에는 화면의 숫자와 장면 길이가 갈려 있다.

## 9. 미해결 결정사항

- 문제 인덱스(`Q2 / 4`) 표기 채택 여부. D1 시안이 발주 범위에 없던 요소로 넣었고 빼도 다른 좌표에
  영향이 없다 — 지금은 구현돼 있으므로 "빼기로 하면 뺀다" 쪽이다.
