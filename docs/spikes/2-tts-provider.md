# 스파이크 #2 — 한국어 TTS provider 선정

- 이슈: [#2](https://github.com/smc5720/Youtube-Shorts-Maker/issues/2)
- 일자: 2026-08-06
- 재현: `pip install edge-tts` 후 `python docs/spikes/2-tts-provider/harness.py`
  (FFmpeg·ffprobe가 PATH에 있어야 한다. 측정에 쓴다.)
  — 원자료 `docs/spikes/2-tts-provider/results.json`, 샘플 `docs/spikes/2-tts-provider/samples/` (39개)
- 실측 환경: `edge-tts` 7.2.8, Python 3.13.2, Windows 11

---

## 1. 결론

**MVP 기본 provider는 Edge TTS, 기본 음성은 `ko-KR-SunHiNeural`로 한다.**

근거 — 네 가지가 동시에 성립한다.

1. **선택지가 실질적으로 하나였다.** PRD 10장의 후보 4개 중 Kokoro는 한국어를 지원하지
   않아 합성 전에 탈락했고(3.1), OpenAI TTS·ElevenLabs는 유료 API 키가 필요해
   "무료 또는 로컬 실행이 쉬운 provider"라는 PRD 7.5의 기본값 조건에서 벗어난다(3.2).
2. **`duration`을 실측으로 확정할 수 있다.** 컨테이너 헤더 값과 실제 디코딩 값의 최대 차이가
   **0.008초**였다. 두 방법이 일치하므로 측정값을 신뢰할 수 있다. #16의 전제 조건이다(4.1).
3. **재합성이 결정적이다.** 같은 문장을 3회 합성해 길이가 5.11초로 **완전히 동일**했다.
   #16이 세그먼트 캐시를 두고 재실행 시 길이를 다시 측정해도 값이 흔들리지 않는다(4.2).
4. **숫자·단위·기호를 한국어로 펼쳐 읽는다.** 검사한 21개 토큰 전부가 기대 한국어 읽기
   길이와 일치했다(4.4). 다만 이 방법은 총량 검사이며 정확한 발음을 확인하지 못한다.

`ko-KR-SunHiNeural`을 기본 음성으로 두는 이유는 **같은 문장을 가장 짧게 읽기** 때문이다.
`ko-KR-InJoonNeural`은 모든 문장에서 8~18% 길고(4.6), 쇼츠는 60초 상한이 있어 낭독 길이가
곧 담을 수 있는 문제 수다. 세 음성 모두 위 1~4를 동일하게 만족하므로 이 선택은
**config에서 바꾸면 되는 기본값**이며 되돌리는 비용이 없다.

### 이 결론이 규정하지 않는 것

- **음질·자연성은 판단하지 않았다.** 청취가 필요하고 이 스파이크는 청취하지 않았다.
  샘플 39개를 남겼으니 7장의 체크리스트로 확인한 뒤 필요하면 음성만 교체한다.
  **음질이 기각 사유가 되면 provider 자체를 다시 열어야 한다** — 대안은 5.2에 있다.
- **유료 후보와 비교하지 않았다.** OpenAI TTS·ElevenLabs를 실제로 합성해 보지 않았으므로
  "Edge TTS가 더 좋다"가 아니라 "Edge TTS가 무료 조건을 만족하는 유일한 후보였다"가 결론이다.
- **상업적 사용·배포를 보증하지 않는다.** edge-tts는 Microsoft의 비공식 엔드포인트를
  호출한다. 개인 로컬 사용을 전제한 결정이며, 채널을 수익화하거나 도구를 배포하는 단계에서는
  5.1의 리스크를 다시 봐야 한다.
- **오프라인 동작은 확보되지 않았다.** Edge TTS는 네트워크 호출이다. 스파이크 #1의 LLM
  결정과 같은 성질의 제약이며, MVP에 오프라인 요구가 없다는 전제를 공유한다.

## 2. 실험 방법

12개 문장 × 한국어 음성 3개 = **36회 합성**, 추가로 결정성 확인 3회. 총 39개 샘플.

문장은 퀴즈 장면 role에 대응시켜 골랐다.

| role | 문장 수 | 목적 |
| --- | --- | --- |
| `question` | 2 | 질문 낭독. 물음표 억양, 퍼센트 기호 |
| `answer` | 3 | **실제 정답 낭독.** 퀴즈 스펙 0장의 TTS 범위가 "질문 + 정답"이고 해설은 자막만이므로 정답 낭독은 짧다 |
| `explanation_probe` | 5 | 해설 길이의 문장. 숫자·단위·고유명사 발음 검사와 길이 상한 확인용 |
| `hook` / `cta` | 2 | 현 스펙은 낭독하지 않지만, 낭독을 추가할 때의 길이를 미리 확인 |

측정 항목과 그 방법은 하네스 상단 독스트링에 있다. 요점은 **길이를 두 가지 방법으로 따로
재서 비교한다**는 것이다 — MP3 컨테이너 헤더는 추정치일 수 있어서, `ffprobe`의
`format=duration`과 `ffmpeg -f null`로 실제 디코딩한 값을 함께 기록했다.

**측정하지 않은 것**: 음질·자연성(청취 필요), 유료 후보(키 없음), Kokoro(한국어 미지원).

## 3. 후보 심사

### 3.1 Kokoro — 한국어 미지원으로 탈락

공식 [`VOICES.md`](https://huggingface.co/hexgrad/Kokoro-82M/raw/main/VOICES.md)의 언어
섹션은 9개다: American English(`a`), British English(`b`), Japanese(`j`),
Mandarin Chinese(`z`), Spanish(`e`), French(`f`), Hindi(`h`), Italian(`i`),
Brazilian Portuguese(`p`). **한국어 섹션이 없다.**

2차 자료(리뷰 사이트, 소개 페이지) 여러 곳이 "한국어 지원"이라고 적고 있으나 공식 모델
카드와 저장소에는 근거가 없다. PRD 14.1이 한국어를 1차 타깃으로 확정했으므로 탈락이다.

PyTorch를 포함한 2~3GB를 내려받기 **전에** 문서로 확인해 설치를 아꼈다.

### 3.2 OpenAI TTS / ElevenLabs — 무료 기본값 조건에서 제외

PRD 7.5는 MVP 기본값을 "무료 또는 로컬 실행이 쉬운 TTS provider"로 못박았다. 두 후보는
API 키와 과금이 필요하므로 **기본값 후보가 아니다.** 실측 대신 공개 자료로 성격만 기록한다.

| 후보 | 과금 | 한국어 | 비고 |
| --- | --- | --- | --- |
| OpenAI `gpt-4o-mini-tts` | 오디오 출력 $12/1M 토큰, 분당 약 $0.015 | 지원 목록에 포함 | OpenAI 스스로 "내장 음성은 영어에 최적화되어 있어 다국어 발음·자연성은 대표 스크립트로 검증하라"고 안내한다 |
| ElevenLabs Multilingual v2 | 문자 1개 = 크레딧 1개. $5 플랜 기준 1,000자당 약 $0.17 | 29개 이상 언어 | 음질 평이 가장 좋은 축이지만 월 구독 구조다 |

영상 1편(4문제, 낭독 약 30초, 약 200자) 기준으로 보면 OpenAI는 편당 1센트 미만,
ElevenLabs는 편당 3~4센트 수준이다. **비용이 결정을 좌우하는 규모가 아니다.**
따라서 유료 후보는 "돈 때문에 못 쓴다"가 아니라 **"기본값은 키 없이 돌아야 한다"**는
이유로 제외되며, 음질이 문제가 되면 유료 provider로 승격하는 것이 자연스러운 다음 수순이다.
그때 필요한 것은 5.3의 인터페이스뿐이다.

## 4. Edge TTS 실측 결과

### 4.1 길이 측정 가능성 — 두 방법이 0.008초 안에서 일치

36개 샘플 전부에서 컨테이너 헤더 길이와 디코딩 길이의 차이가 **최대 0.008초**였다.
30fps 한 프레임이 0.033초이므로 **프레임보다 작은 오차**다.

`duration`을 실측으로 확정하는 #16은 이 값 하나에 의존한다. 값이 신뢰할 수 없으면
자막·오버레이·효과음이 전부 어긋나므로, "측정할 수 있다"에서 멈추지 않고 서로 다른 두
방법이 같은 답을 주는지까지 확인했다.

구현 시에는 **컨테이너 값(`ffprobe format=duration`)을 쓴다.** 디코딩보다 훨씬 빠르고
차이가 프레임 이하다.

### 4.2 결정성 — 3회 합성 결과가 완전히 동일

같은 문장(`약 6,650km로 세계에서 가장 긴 강입니다.`)을 3회 합성해 디코딩 길이가
**5.11초 / 5.11초 / 5.11초**로 같았다.

의미 — #16이 "세그먼트가 이미 있고 텍스트가 안 바뀌면 재합성을 건너뛴다"는 캐시를 둘 수
있다. 재합성해도 길이가 같으므로 캐시 적중과 미적중이 다른 결과를 내지 않는다.

### 4.3 목표치 대비 실제 길이 — 60%에서 196%까지 벌어진다

디코딩 길이(초), `ko-KR-SunHiNeural` 기준. 목표치는 퀴즈 스펙 2장의 값이다.

| 문장 | role | 실제 | 목표 | 목표 대비 |
| --- | --- | --- | --- | --- |
| 세계에서 가장 긴 강은? | question | 2.66 | 3.0 | 89% |
| 지구 표면의 약 71%를 덮고 있는 것은? | question | 4.32 | 3.0 | **144%** |
| 나일강 | answer | 1.80 | 3.0 | **60%** |
| 직지심체요절 | answer | 2.20 | 3.0 | 73% |
| 페이턴트 모터바겐 | answer | 2.49 | 3.0 | 83% |
| 물의 화학식은 H2O입니다. | explanation | 3.43 | 3.0 | 114% |
| 에베레스트산의 높이는 8,848m입니다. | explanation | 4.75 | 3.0 | 158% |
| 약 6,650km로 세계에서 가장 긴 강입니다. | explanation | 5.11 | 3.0 | 170% |
| 현존하는 대한민국 최초의 금속활자본은 직지심체요절입니다. | explanation | 5.49 | 3.0 | 183% |
| 1969년 7월 20일, 아폴로 11호가 달에 착륙했습니다. | explanation | 5.88 | 3.0 | **196%** |

**최소 1.80초, 최대 5.88초 — 3.3배 차이다.** PRD 14.1의 타이밍 결정(초 단위 값은 목표치이며
`duration`은 실측으로 확정)이 옳았음을 뒷받침한다. 고정 3초를 썼다면 "나일강"은 1.2초를
무음으로 낭비하고, 해설 문장은 2.9초가 잘려 나갔다.

### 4.4 숫자·단위·고유명사 발음 — 21개 토큰 전부 기대 길이와 일치

청취 대신 쓴 방법: WordBoundary가 토큰별 지속시간을 주므로, 순수 한글 토큰에서 음절당
소요 시간을 구한 뒤 문제 토큰의 지속시간을 음절 수로 환산해 올바른 한국어 읽기와 비교했다.

`ko-KR-SunHiNeural` 기준 음절당 0.177초. 환산 결과:

| 토큰 | 기대 읽기 | 기대 음절 | 환산 음절 | 판정 |
| --- | --- | --- | --- | --- |
| `6,650km로` | 육천육백오십킬로미터로 | 11 | 9.8 | 통과 |
| `1969년 7월 20일` | 천구백육십구년칠월이십일 | 12 | 12.4 | 통과 |
| `11호가` | 십일호가 | 4 | 3.3 | 통과 |
| `8,848m입니다` | 팔천팔백사십팔미터입니다 | 12 | 13.1 | 통과 |
| `71%를` | 칠십일퍼센트를 | 7 | 6.2 | 통과 |
| `H2` / `O입니다` | 에이치투 / 오입니다 | 4 / 4 | 3.5 / 3.8 | 통과 |

음성 3개 × 토큰 7개 = **21개 전부 허용 구간(±35%) 안**이다.

**이 방법의 한계를 분명히 해 둔다.** 이것은 총량 검사다. 엔진이 숫자를 건너뛰거나 자릿수를
영어로 읽는 것 같은 **큰 실패는 잡아내지만**, 예를 들어 `km`를 "킬로미터"로 읽는지
"케이엠"으로 읽는지는 음절 수가 비슷해 구별하지 못한다. 정확한 발음은 7장의 청취로 확인한다.

가장 눈여겨볼 것은 `H2O`다. WordBoundary가 `H2`와 `O입니다`를 **별도 토큰으로 쪼갰다**.
화학식·수식이 정답이나 해설에 들어가면 낭독이 어색할 가능성이 있으니 청취 우선순위가 높다.

### 4.5 합성 속도 — 문장당 0.3~1.4초, 후보 변별에 쓸 수 없다

| 음성 | 최소 | 중앙 | 최대 |
| --- | --- | --- | --- |
| `ko-KR-SunHiNeural` | 0.35 | 0.44 | 0.71 |
| `ko-KR-InJoonNeural` | 0.36 | 0.49 | 0.68 |
| `ko-KR-HyunsuMultilingualNeural` | 0.30 | 0.48 | 1.41 |

첫 실행에서는 `Hyunsu`가 1.0~1.7초로 느렸지만 재실행에서 다른 음성과 같아졌다.
**네트워크 지연이지 음성의 성질이 아니다.** 합성 속도는 후보를 변별하지 못한다.

영상 1편은 낭독 장면이 8~10개이므로 총 합성 시간은 **5초 이하**다. 렌더링 시간에 비해
무시할 수 있다.

### 4.6 음성 3개 비교 — InJoon이 일관되게 길다

디코딩 길이(초).

| 문장 | SunHi (F) | InJoon (M) | Hyunsu (M) |
| --- | --- | --- | --- |
| 세계에서 가장 긴 강은? | 2.66 | 3.02 | 2.85 |
| 나일강 | 1.80 | 2.13 | 1.77 |
| 직지심체요절 | 2.20 | 2.37 | 2.01 |
| 1969년 7월 20일, 아폴로 11호가… | 5.88 | 6.28 | 5.92 |
| 후킹 문장 | 4.46 | 5.11 | 4.10 |

`InJoon`은 12개 문장 전부에서 `SunHi`보다 길다(8~18%). 4문제 영상이면 낭독 총량에서
3~5초 차이가 나고, 이는 문제 하나를 더 담을 수 있는지를 가른다. 그래서 기본값은 `SunHi`다.

`Hyunsu`(Multilingual)는 가장 짧지만 합성 지연 변동이 크고, 다국어 음성이라 한국어 전용
음성보다 한국어 억양이 불안할 여지가 있다. 7장 청취에서 함께 판단한다.

### 4.7 부수 소득 — WordBoundary가 있으니 #17에 Whisper가 필요 없을 수 있다

`edge_tts.Communicate(..., boundary="WordBoundary")`로 호출하면 **토큰별 오프셋과
지속시간**이 함께 온다. 예:

```
세계에서(0.000~0.500) 가장(0.500~0.887) 긴(0.887~1.150) 강은(1.150~1.800)
```

PRD 7.6은 word-level timestamp 개선에 Whisper/Faster Whisper를 전제했다. **TTS가 이미
정답을 주고 있으므로 전사가 필요 없다.** 전사는 추정이고 이 값은 합성 엔진의 실제 타이밍이라
정확도도 더 높다.

두 가지 주의점.

- `boundary`의 **기본값은 `SentenceBoundary`**다. 문장 단위로 합성하는 이 파이프라인에서는
  문장 경계가 문장 전체 하나뿐이라 쓸모가 없다. `WordBoundary`를 명시해야 한다.
  (처음에 이걸 놓쳐서 이벤트가 0개로 측정됐다.)
- **이벤트의 `text`는 정규화된 발음이 아니라 원문 토큰**이다. 자막 텍스트로는 그대로 쓸 수
  있지만 발음 확인에는 쓸 수 없다.

이 발견은 #17과 #33의 범위를 줄인다. 해당 이슈 리파인먼트 때 반영한다.

### 4.8 타임라인 재계산 — 4문제가 60초에 들어간다

4.3의 실측값에 PRD 7.5.1의 패딩(앞 0.3초 + 뒤 0.5초)을 적용해 `SunHi` 기준으로 계산했다.

| 장면 | 길이 근거 | 초 |
| --- | --- | --- |
| `hook` | 고정 | 3.0 |
| `question` × 4 | 실측 중앙 3.5 + 패딩 0.8 | 4.3 × 4 = 17.2 |
| `countdown` × 4 | 고정 4.0 | 16.0 |
| `answer` × 4 | 실측 중앙 2.2 + 패딩 0.8 | 3.0 × 4 = 12.0 |
| `cta` | 고정 | 4.0 |
| **합계** | | **52.2** |

PRD 6.3의 45~60초 안에 들어간다. **정답 낭독이 짧다는 것이 여유의 원천이다** — 해설을
낭독하는 설계였다면 정답 장면이 3.0초가 아니라 5.9초가 되어 합계가 63.8초로 상한을 넘는다.
퀴즈 스펙 0장의 "해설은 자막만" 결정이 길이 예산 측면에서도 옳다.

다만 **정답 장면 3.0초 안에 해설 자막을 읽혀야 한다.** 낭독은 2.2초면 끝나지만 자막
"약 6,650km로 세계 최장"을 읽는 데는 그보다 오래 걸린다. PRD 7.5.1의 `min_duration`
1.2초는 한국어에서 한 번도 걸리지 않았으므로(가장 짧은 정답 1.80초) 이 문제를 막아주지
못한다. **`answer` role에는 자막 읽기 시간을 보장하는 별도 하한이 필요할 수 있다.**
#12(장면 템플릿)와 #16(duration 보정)에서 확인할 항목으로 남긴다.

## 5. 리스크와 대응

### 5.1 edge-tts는 비공식 엔드포인트다 — 이 결정의 가장 큰 약점

`edge-tts`는 Microsoft Edge의 "Read Aloud" 기능이 쓰는 **문서화되지 않은 엔드포인트**를
호출한다. 공식 SDK가 아니다.

확인된 사실.

- 상류 저장소가 스스로 **"중요한/미션 크리티컬한 용도로 이 라이브러리를 쓰는 것은 매우
  나쁜 생각"**이라고 경고한다. 상업적 사용은 Microsoft 약관을 직접 확인하라고 안내한다.
- Microsoft가 이미 **단기 anti-abuse 토큰을 요구하도록 서비스를 변경**했고 클라우드 IP
  대역 필터링을 강화했다. 즉 **예고 없이 깨질 수 있고, 실제로 깨진 전례가 있다.**
- SSML·감정 태그를 쓸 수 없다. Edge 자체가 쓰는 기능으로 제한된다.

PRD 8장이 "라이선스·정책 리스크가 낮은 소스만 사용"을 요구하므로 이 리스크를 결정문에
명시적으로 남긴다. 이 결정은 **개인 로컬 사용 전제**에서만 유효하다.

### 5.2 대응 — 승격 경로를 미리 정해 둔다

깨지거나 범위가 상업적 사용으로 넓어질 때 갈 곳을 지금 정한다.

| 상황 | 승격 대상 | 마이그레이션 비용 |
| --- | --- | --- |
| 상업적 사용·배포, 또는 엔드포인트가 막힘 | **Azure AI Speech** (공식) | **낮다.** 같은 Azure Neural 음성이라 `ko-KR-SunHiNeural` 음성 이름이 그대로 유지된다. 목소리가 바뀌지 않으므로 이미 만든 영상과 톤이 이어진다. 무료 티어 월 50만 자, 이후 Neural $16/1M 자 |
| 음질이 기각당함 | ElevenLabs 또는 OpenAI TTS | 중간. 음성이 바뀌므로 톤이 달라진다 |
| 오프라인이 요구사항으로 승격 | **MeloTTS-Korean** (MIT, CPU 추론) | 중간. 한국어를 실제로 지원하고 라이선스가 MIT다. Kokoro와 달리 후보 자격이 있다 |

**PRD 10장의 로컬 후보를 Kokoro에서 MeloTTS로 교체한다.** Kokoro는 한국어가 없어 후보가
될 수 없고, MeloTTS는 한국어 모델이 공개되어 있으며 MIT다.

Azure AI Speech가 같은 음성 이름을 제공한다는 점이 이 결정의 안전장치다. edge-tts를
쓰다가 막혀도 **목소리를 유지한 채** 공식 경로로 옮길 수 있다.

### 5.3 provider 인터페이스에 요구할 것 (#14 입력)

이번 실측에서 실제로 필요했던 것만 적는다.

- **합성은 세그먼트 단위**로 한다. 입력은 텍스트 하나, 출력은 오디오 파일 하나.
  PRD 7.5.2의 `audio/seg-{index:03d}.mp3`에 대응한다.
- **길이를 반환하지 말고 파일을 측정한다.** provider가 보고하는 값을 신뢰하는 대신
  `ffprobe`로 재는 것을 공통 코드에 둔다. provider마다 보고 정확도가 다르다.
- **단어 타이밍은 선택 기능(optional capability)으로 둔다.** Edge TTS는 주지만 다른
  provider는 못 준다. 인터페이스가 이걸 필수로 요구하면 provider 교체가 막히고,
  아예 없으면 4.7의 이득을 못 쓴다. `supports_word_timings` 같은 조회 지점을 둔다.
- **음성 이름은 provider별 문자열로 그대로 통과시킨다.** 추상화하지 않는다. 5.2의 Azure
  승격이 "같은 음성 이름"을 근거로 싸지는 것이므로, 이름을 자체 어휘로 매핑하면 그 이득이 사라진다.
- SSML은 인터페이스에 넣지 않는다. Edge TTS가 못 쓴다.

## 7. 남은 것 — 청취 체크리스트

음질은 사람이 들어야 한다. `docs/spikes/2-tts-provider/samples/`에서 아래를 확인한다.
파일명은 `{문장id}__{음성}.mp3`다.

1. **`a_formula__*.mp3`** — "물의 화학식은 H2O입니다." WordBoundary가 `H2`와 `O`를 쪼갰다.
   "에이치투오"로 자연스럽게 이어 읽는지, "에이치 이 오"처럼 끊기는지. **우선순위 1위.**
2. **`a_number_unit__*.mp3`** — `6,650km`를 "육천육백오십 킬로미터"로 읽는지,
   "육천육백오십 케이엠"으로 읽는지. 4.4의 총량 검사가 구별하지 못한 지점이다.
3. **`a_height_unit__*.mp3`** — `8,848m`의 `m`을 "미터"로 읽는지 "엠"으로 읽는지.
4. **`a_hanja_noun__*.mp3`** — "직지심체요절" 한자어 고유명사 발음.
5. **`a_foreign_noun__*.mp3`** — "페이턴트 모터바겐" 외국어 음역.
6. **`q_plain__*.mp3`** — 물음표 억양이 질문처럼 올라가는지. 퀴즈 타입에서 중요하다.
7. **음성 선택** — `SunHi`(여) / `InJoon`(남) / `Hyunsu`(남, 다국어) 중 채널 톤에 맞는 것.
   길이만 보면 `SunHi`가 유리하다(4.6).

1~3에서 문제가 나오면 **숫자·단위를 한글로 미리 펼쳐서 TTS에 넘기는 전처리**가 필요하다.
`quiz_generator`가 해설을 만들 때 `6,650km` 대신 "약 육천육백오십 킬로미터"로 쓰게 하거나,
TTS 앞단에 정규화 단계를 둔다. #15 리파인먼트 때 판단한다.

6에서 문제가 나오면 문장 끝 물음표 유지 또는 SSML이 필요하지만 **Edge TTS는 SSML을 쓸 수
없다**(5.1). 그 경우 provider 승격이 검토 대상이 된다.
