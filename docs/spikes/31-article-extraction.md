# 링크 본문 추출 — 결정과 실측 (#31)

> PRD 14.2에 남아 있던 두 항목("어떤 라이브러리로 시작할지", "유료·로그인·동적 렌더링
> 페이지를 MVP에서 제외할지")의 답이다. 원자료는
> [`31-article-extraction/results.json`](31-article-extraction/results.json),
> 하네스는 [`harness.py`](31-article-extraction/harness.py)다.

- 이슈: [#31](https://github.com/smc5720/Youtube-Shorts-Maker/issues/31)
- 일자: 2026-08-19
- 재현: `.spike\Scripts\python docs\spikes\31-article-extraction\harness.py`
  (`py -m venv .spike && .spike\Scripts\pip install trafilatura readability-lxml justext`)
- 실측 환경: Windows 11 (10.0.26100), Python 3.13.2, trafilatura 2.2.0 /
  readability-lxml 0.8.4.1 / jusText 3.0.2 / lxml 6.1.2
- **기사 URL은 RSS에서 그때그때 뽑는다.** 다시 돌리면 다른 기사가 잡히므로 아래 절대값은
  그날의 스냅숏이고, 반복해서 확인할 것은 추출기 사이의 **차이**다.

## 1. 결정

**본문 추출은 trafilatura로 한다. 단 선택 의존성(`source` extra)이고 `--url`을 실제로 쓸 때만
import한다.**

**유료·로그인·동적 렌더링 페이지는 MVP에서 제외한다. 그러나 "페이지 유형을 판별해서 거부"하지
않는다** — 판별이 불가능하다는 것이 아래 3장의 실측 결과다. 거부는 관측 가능한 신호 셋에만
건다.

1. HTTP 상태가 200이 아니다 (유료 매체는 401/403으로 나타난다)
2. `Content-Type`이 HTML이 아니다
3. 추출된 본문이 없거나 임계(기본 300자) 미만이다

셋 중 하나면 실패 사유를 남기고 `--text-file`로 안내한다. 그 밖의 200은 **받아서
`source.json`에 남기고 사람이 본다** — 로그인 안내문이 임계를 넘겨 통과하는 경우가 실제로
있고(3.2), 그것을 자동으로 가르려는 시도는 정상 기사를 함께 버린다.

곁들여 확정한 것 둘.

- **User-Agent는 도구 이름을 밝힌다. 브라우저로 위장하지 않는다** — 위장이 필요하지 않다는
  것이 실측이다 (4장).
- **robots.txt를 조회하지 않는다.** 사용자가 지정한 단일 URL을 한 번 가져오는 것은 크롤링이
  아니고, MVP는 링크를 따라가지 않는다. 링크를 수집하는 경로가 생기면 그때 다시 본다.

### 이 결론이 규정하지 않는 것

- **요약·대본 품질** — 추출된 본문이 무엇이 되는지는 #32다. 이 문서는 "본문이 본문인가"까지다.
- **`source.json` 스키마** — 필드는 #31 하위 이슈가 `schemas/`에 확정한다.
- **동적 렌더링 페이지의 장기 대책** — 헤드리스 브라우저 동봉은 이번 결정이 미룬 것이지 닫은
  것이 아니다 (5장).

## 2. 추출기 비교

같은 HTML을 넷에 넣었다. `junk`는 본문에 섞이면 안 되는 껍데기 문구(회원가입, 많이 본 뉴스,
기사제보 …)가 몇 개 나왔는지다.

| 페이지 | stdlib | trafilatura | readability | justext |
| --- | ---: | ---: | ---: | ---: |
| 기사 (연합뉴스, 단신) | 5,154자 (junk 1) | **478자** | 536자 | **0자** |
| 기사 (한겨레) | 3,504자 | **1,022자** | 1,070자 | 548자 |
| 기사 (매일경제) | 10,623자 (junk 3) | **2,202자** | 2,223자 | 722자 |
| 위키백과 (긴 문서) | 93,493자 (junk 1) | **80,787자** | 29,328자 | 24,496자 |
| 채용 공고 (CSR) | 1,522자 (junk 2) | **963자** | 338자 | 365자 |
| NYT 섹션 | 5,297자 | 3,267자 | 182자 | **0자** |
| x.com (JS 필요) | 170자 | 258자 | 228자 | 0자 |
| 네이버 카페 (로그인) | 9,920자 (junk 1) | 800자 | 104자 | 0자 |

**jusText는 8개 중 4개에서 0자를 냈고 그중 하나가 정상 기사다** (연합뉴스 단신 — 다른 셋이
478~536자를 낸 페이지다). 한국어 stoplist와 문단 길이 임계로 판정하는 방식이라 단락이 짧은
기사에서 본문 전체를 boilerplate로 지운다. 통과한 경우에도 리드 문장을 잃는다(한겨레 548자 —
본문은 1,022자다). 탈락.

**readability는 기사에서는 비슷한 양을 내지만 무엇을 냈는지가 다르다.** 연합뉴스에서
`이미지 확대 / 전북경찰청 / [촬영 나보배]`로 시작하고, 채용 공고에서는 **본문 대신 저작권
고지 338자**를, NYT 섹션에서는 **182자**를 냈다. 위키백과에서는 80,787자 중 29,328자만
남겼다. 같은 하네스로 돌린 앞선 실행에서도 매일경제 기사 본문 1,143자 중 **436자**만 냈다 —
빠진 쪽이 리드였다.

**stdlib(표준 라이브러리 `html.parser`)은 본문의 3~10배를 낸다.** 내비게이션·구독 유도·기자
프로필이 그대로 들어오고, `junk` 문구가 8개 중 5개에서 검출됐다(매일경제는 회원가입·로그인·
구독하기 셋). 여기에 **인코딩 협상을
직접 해야 한다** — 네이버 카페가 `charset=MS949`(meta는 `KSC5601`)로 오고, utf-8로 디코드하면
글자가 통째로 깨진다. trafilatura는 바이트를 그대로 받아 이것을 처리했다.

**trafilatura는 8개 전부에서 리드 문장부터 시작했고 junk가 7개에서 0이다.** 남은 하나는
위키백과의 "로그인" 1건인데 stdlib·readability도 함께 검출했다 — 껍데기가 아니라 문서 본문에
있는 단어다. 메타데이터도 함께
나온다 — 세 기사 모두 `title`·`author`·`date`(`2026-08-19`)가 정확했다. `source.json`이 요구하는
제목이 여기서 그대로 나온다 (PRD 7.1).

속도는 판단 근거가 아니다. 가장 느린 경우가 위키백과 808ms이고 일반 기사는 25~43ms인데,
같은 파이프라인의 LLM 호출이 수십 초다.

### 비용

| 항목 | 값 |
| --- | --- |
| 새로 설치되는 패키지 | 12개 (babel, courlan, htmldate, justext, lxml, dateparser, regex, tld, tzlocal, charset-normalizer, lxml_html_clean, trafilatura) |
| 디스크 | 약 55MB (babel 32MB, lxml 10MB가 대부분) |
| `import trafilatura` | 810ms |

readability-lxml은 5개(약 15MB), jusText는 3개다. **이 저장소의 런타임 의존성은 지금 둘뿐이고**
(`pyyaml`, `edge-tts`) 렌더러조차 의존성을 늘리지 않았으므로(#19), 12개는 그냥 더할 수 있는
크기가 아니다. 그래서 셋을 나눠 정했다.

- **정확도는 타협하지 않는다.** readability·jusText가 아끼는 것은 40MB이고 잃는 것은 "본문
  대신 저작권 고지"다. 그 오류는 #32의 요약을 지나면 **그럴듯한 헛소리**가 되어 드러나지 않는다.
- **대신 필수 의존성으로 만들지 않는다.** `--url`은 두 번째 쇼츠 타입에서야 쓰이므로
  `pip install youtube-shorts-maker[source]`로 연다. 없는데 `--url`을 주면 run 디렉터리를
  만들기 전에 설치 방법을 말하며 멈춘다 — `validate_providers`·`validate_tts_provider`가 이미
  서 있는 자리다.
- **import는 지연시킨다.** 810ms는 `--topic` 실행이 낼 이유가 없는 비용이다.

**되돌릴 조건** — 앱이 생성까지 하게 되면(지금 생성은 CLI 전용이다) 선택 의존성은 의미가
없어진다. 동결 배포(PyInstaller onedir, #26)에 55MB가 들어오고 `--hidden-import`가 필요해지므로,
그때 필수로 승격한다.

## 3. 유료·로그인·동적 렌더링 페이지

### 3.1 상태 코드로 드러나는 것

WSJ은 **401**을 준다. 봇 차단·유료 매체는 대체로 여기서 걸리고, 이 경우는 명확히 거부할 수
있다.

### 3.2 상태 코드로 드러나지 않는 것 — 길이 임계가 가르지 못한다

x.com은 **200과 함께 "JavaScript를 사용할 수 없습니다" 안내문 258자**를 준다. 네이버 카페는
**200과 함께 로그인·알림 안내문 800자**를 준다. 둘 다 추출기가 무엇이든 그 안내문을 본문으로
낸다 — 껍데기가 아니라 페이지에 실제로 있는 유일한 글이기 때문이다.

문제는 그 800자가 **정상 기사와 겹친다**는 것이다.

| | 글자 수 |
| --- | ---: |
| 네이버 카페 로그인 안내문 | 800자 |
| 한겨레 기사 (이 스냅숏) | 1,022자 |
| 연합뉴스 단신 (이 스냅숏) | **478자** |
| 앞선 실행의 한겨레 정치 단신 | **735자** |

앞선 실행에서는 **정상 기사(735자)가 로그인 안내문(800자)보다 짧았다.** 즉 임계를 카페를
거를 만큼 올리면 단신 기사가 함께 잘린다. 그래서 임계의 목적은 "안내문 걸러내기"가 아니라
**"빈 본문 걸러내기"** 로 좁히고, 기본값은 관측된 가장 짧은 정상 기사(478자)와 JS 안내문
(258자) 사이인 **300자**로 둔다.

### 3.3 도메인·기술 스택으로도 가르지 못한다

원티드 채용 공고는 CSR로 알려진 페이지인데 SSR 폴백이 있어 **963자가 정상 추출된다.** 반대로
x.com은 200을 주면서 본문이 없다. "동적 렌더링 사이트 목록"을 들고 거르는 구현은 이 두 경우를
모두 틀린다.

**그래서 판별하지 않는다.** 거부는 1장의 세 신호에만 걸고, 통과한 것은 사람이 본다 —
추출 글자 수와 제목을 콘솔에 내고 본문 전체는 `source.json`에 남긴다.

## 4. User-Agent — 위장할 필요가 없다

| 페이지 | 도구 이름 UA | 브라우저 UA | UA 없음 |
| --- | --- | --- | --- |
| 연합뉴스 | 200 | 200 | 200 |
| 한겨레 | 200 | 200 | 200 |
| 매일경제 | 200 | 200 | **403** |
| 위키백과 | 200 | 200 | **403** |

**`User-Agent`를 보내야 하지만 브라우저일 필요는 없다.** `shorts-maker/0.1 (+저장소 URL)`로
전부 200이었고, 헤더를 아예 빼면 매일경제와 위키백과가 403을 준다(위키백과는 UA 정책을
명시한다). 위장 UA는 얻는 것이 없고 차단 정책과 싸우는 코드를 부른다.

## 5. 부수적으로 걸린 것

- **Python 3.13의 `ssl.create_default_context()`는 `VERIFY_X509_STRICT`를 기본으로 켠다.**
  TLS를 가로채는 사내 프록시의 CA가 basicConstraints를 critical로 표시하지 않아, 이 환경에서는
  모든 HTTPS 요청이 `certificate verify failed: Basic Constraints of CA cert not marked
  critical`로 실패했다. 플래그를 끄면(체인 검증은 유지) 통과한다. **`--url` 경로는 이런 환경을
  만나면 전부 실패하므로**, 실패 메시지가 `ssl` 원문을 그대로 실어야 사용자가 프록시 문제임을
  알 수 있다. 하네스는 플래그를 끄지만 **제품 코드가 무엇을 할지는 하위 이슈의 결정**이다 —
  검증을 끄는 것이 아니라 `SSL_CERT_FILE` 안내가 먼저다.
- **응답 인코딩이 utf-8이 아닌 한국어 사이트가 아직 있다** (네이버 카페 `MS949`). 바이트를
  그대로 추출기에 넘기고, 우리 코드가 `.decode()`를 먼저 하지 않는다.
- **표준 라이브러리 `urlopen`에 크기 상한이 없다.** 위키백과 문서 하나가 1.5MB였다. 하위
  이슈에서 상한과 타임아웃을 함께 정한다.
