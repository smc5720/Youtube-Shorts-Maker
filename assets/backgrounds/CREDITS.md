# 배경 프리셋 출처와 라이선스

`presets.json`의 색값은 **D1 영상 디자인 확정 스펙 6.2**에서 그대로 옮겼다
(`docs/design/d1-video-design-spec.md`). 제3자 파일이 아니라 이 프로젝트의 정의값이므로
**이 저장소의 라이선스를 따르고, 재배포와 앱 동봉에 조건이 없다.** 표기 문구도 필요하지 않다.

| --- | --- | --- |
| `deep_navy` | 딥 네이비 | 단색 `#101A33` |
| `purple_gradient` | 퍼플 그라디언트 | 수직 `#1B0B2E`(위) → `#4A1052`(아래) |
| `deep_teal_gradient` | 딥 틸 그라디언트 | 수직 `#06231F`(위) → `#0B3A2C`(아래) |

확정 스펙의 `B1`·`B2`·`B3`이 위 순서다. 이름을 `b1`로 두지 않은 이유는 설정 파일과
`project.json`에 사람이 적는 값이기 때문이다 — 번호는 무엇이 바뀌는지 알려주지 않는다.

## 이미지 파일이 없는 이유

확정 스펙 6.2가 **단색과 수직 2스톱 그라디언트만** 허용한다 (이미지 배경·노이즈·비네트 없음).
FFmpeg가 `color`·`gradients` 필터로 캔버스에서 직접 그릴 수 있으므로 PNG를 굽는 것은 1080×1920
무손실 이미지 3장을 저장소에 넣고 색을 고칠 때마다 다시 굽는 일만 늘린다. 그래서 이 디렉터리에
있는 것은 정의값 하나다.

사용자가 자기 이미지·영상을 배경으로 쓰는 경로는 프리셋과 다른 층이다 — `project.json`의
`background.kind`가 `image`/`video`이고 `value`가 그 파일 경로다 (PRD 7.10). 그쪽은 라이선스를
사용자가 확인하며 저장소에 들어오지 않는다.

## 소비하는 쪽

- 이름 → 정의값 조회는 `shorts_maker.assets.background_presets()` 하나다.
- `render.background` 설정이 이 이름을 받고, 없는 이름이면 실행 시작 시점에 오류가 난다.
- 렌더러(#19)가 `project.json`의 `background`(`kind: preset` / `value: <이름>`)를 읽어
  FFmpeg 필터로 옮긴다. **스톱이 1개면 단색, 2개면 수직 그라디언트**이고 종류를 따로 적지
  않는다 — 확정 스펙이 수직 2스톱만 허용하므로 스톱 수가 종류를 결정한다.
- 색과 배경의 명도비는 `tests/test_visual_assets.py`가 커밋된 값에서 다시 계산한다. 측정값은
  확정 스펙 6.3에 있다.
